# Spec: 媒体标签占位化——投喂条目不再携带图形数据

## Problem Statement

宿主快照（序列化投喂 LLM 的 HTML）目前原样保留媒体类标签：SVG 的路径数据（成串坐标数字）、`img` 的 `src`（内联图时是整段 base64）、以及 picture/source/video/audio/canvas/map 的媒体数据。这些图形数据对翻译毫无贡献，却被计入条目与批次字符上限——单个 base64 图就能撑爆一批（`maxCharsPerBatch` 4000），导致批次碎片化、token 浪费、请求变慢。判定侧三者已经一致（svg 硬跳过、img 无文本参与、pre/code 剥除后判空），不一致的正是投喂侧。

## Solution

投喂序列化时，将媒体类标签替换为**同名空占位标签**（移除全部属性与子树）：`<img src="data:...">` → `<img>`，`<svg>…路径…</svg>` → `<svg></svg>`。模型仍能从占位感知"此处有媒体"的语序，图形数据不再进入 prompt。可翻性判定与回显净化行为零变化。

## User Stories

1. 作为页面读者，我希望 SVG 路径数据不进入翻译请求，这样批次不被无意义图形数据撑爆，请求更快更省 token。
2. 作为页面读者，含内联 base64 图的段落能正常进批被翻，不再因单宿主超限独占一批。
3. 作为页面读者，译文语序仍然正确——模型通过占位感知"此处有图"，不会把图形数据当文字描述。
4. 作为扩展维护者，我希望占位规则有纯函数级单元测试锁定，媒体清单变化时测试明确红。
5. 作为扩展维护者，可翻性判定零改动：svg 仍硬跳过、img 仍不参与文本判定、pre/code 仍"判定剥除、投喂保留"。
6. 作为扩展维护者，净化闸门零改动：回显侧不新增媒体禁令（决策 1：仅投喂侧）。
7. 作为页面读者，alt/title 文本随标签一起丢弃，不产生"图片说明"类多余译文（决策 4）。
8. 作为页面读者，译文节点渲染不受影响——占位只存在于投喂文本；模型若回显空 `<img>`，经既有净化后无 src 不渲染、不发请求，无害。

## Implementation Decisions

- 媒体标签清单：`img, svg, picture, source, video, audio, canvas, map`（决策 3 确认）。
- 替换语义：清单内每个元素替换为**同名空元素**——移除全部属性与子树（决策 2：留占位）。
- 落点：宿主快照函数内，既有"剔除 .translate-node"之后追加媒体占位化；在克隆子树上操作，页面真实 DOM 不受影响（"译文节点是唯一 DOM 写入"铁律不变）。
- 批次计数自动受益：占位化后的长度进入既有批次构造的字符统计。
- alt/title 随属性一并移除（决策 4），不做翻译。

## Testing Decisions

- 只测外部行为：输入 HTML 片段 → 输出序列化结果，断言占位形态与计数下降，不断言内部实现。
- 用例：① img 含 base64 src + alt → 输出 `<img>`、alt 消失；② svg 含 path 子树 → `<svg></svg>`；③ picture/source 组合 → 各自空标签；④ pre/code 与普通文本不受影响的回归保护（"与 pre/code 一致"语义：判定剥除、投喂保留）；⑤ 判定侧零改动的既有测试全绿。
- Prior art：tests/host-discovery.test.js（jsdom 注入 document 的纯函数测试）。

## Out of Scope

- 回显净化侧新增媒体禁令（决策 1 明确不做）。
- alt/title 的翻译（决策 4 丢弃）。
- 已翻宿主内追加内容不重翻（既有已知盲区）。
- 回显占位的样式处理（空标签无 src 不渲染，无需处理）。

## Further Notes

- 模型回显占位标签属预期行为：prompt 要求保留标签结构，空占位经净化后无害。
- 未来扩展清单（如 `object`）只需改一处常量。
