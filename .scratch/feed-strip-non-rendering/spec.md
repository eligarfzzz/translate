# Spec: 非渲染标签剥离与剥离后为空的宿主不产生条目（feed-strip-non-rendering）

## Problem Statement

- 宿主发现出口（`discoverEntries`）用 `el.closest(HARD_SKIP_SELECTOR)` 判断候选元素能否成为宿主，这次判断只看候选元素自身及其祖先，不看候选的子孙。候选一旦在出口被接受为宿主，就不再向下访问它的子元素，它内部的 `script`/`style`/`noscript`/`iframe` 从未接受过这份判断。
- 资格判定收集宿主文本时只排除 `pre`/`code` 子树（`nonCodeText` 的 `acceptNode` 仅对祖先链含 `PRE`/`CODE` 的文本节点返回 `REJECT`），脚本、样式、模板里的文本照样计入宿主文本。
- 快照序列化的剥离步骤只有三步：删 `.translate-node`、媒体标签清空子树并保留同名空标签、`input`/`button` 换名 `span`，之后删除全部元素属性。清单里没有脚本、样式、框架、模板等标签，它们随 `innerHTML` 原样进入请求内容。
- 实测后果（用户报错）：Reddit 评论块内的 `<faceplate-loader><script>SML.load([...], 'zh-CN/', 'auto');</script></faceplate-loader>` 被原样发送给模型。同一段内容在输出侧被净化闸门剥掉（净化禁 `script`），所以页面上看不到它，模型却已经收到并处理了它——白花 token，且模型可能围绕它产生无关输出。
- 连带后果一：脚本里的中文进入资格判定的汉字占比计算，使「短英文 + 长中文脚本」的块被判为中文占优，整块跳过，该翻的英文一段都不翻。
- 连带后果二：剥离后实际内容为空的宿主仍会发起请求（例如被媒体步骤清空子树的块），白占一个并发槽、白消耗一次端点调用，并在进度徽标里占一个分母。
- 连带后果三：HTML 注释既不渲染也无人处理，随请求内容送出；实测模型把它原样回显，输出侧净化只删元素（`querySelectorAll("*")` 与空元素规则都够不到注释），于是 `<!--?lit$29506216$-->` 这类噪声出现在译文节点里。

## Solution

宿主发现出口做两件事，二者都只作用于发送给模型的请求内容，页面真实 DOM 一字不动：

1. **剥离非渲染标签**：快照序列化时删除一份固定清单内的元素及其整棵子树——`script`、`style`、`iframe`、`template`、`noscript`、`link`、`meta`、`base`，并删除 HTML 注释节点。删除 `<template>` 元素即连带它的 `content` 一并消失，不需要单独遍历 `content`。
2. **剥离后为空的不发请求**：快照在剥离与清理完成后取文本内容，若整串只由空白构成（空格、制表、换行，以及 NBSP、各类 Unicode 空白、零宽字符——HTML 实体经文本内容取用后已解码，无需实体层特判），则该宿主不产生条目：不建译文节点、不占并发槽、不计入进度徽标的分母与括号。

同时让资格判定与剥离共用同一份清单：收集宿主文本时排除 `pre`/`code` 子树与这份非渲染标签清单，使「脚本里的中文让整段被跳过」不再发生，也使「判定算它有字、实际发送却是空」不再发生。

## User Stories

1. 作为页面读者，我想脚本、样式、框架、模板这些不渲染的内容不进入翻译请求，这样我不会为看不见的代码付 token，模型也不会围绕它们产生无关输出。
2. 作为页面读者，我想宿主内的 `<script>` 内容完全不发送，这样页面上的脚本源码不会因为翻译请求被送到第三方端点。
3. 作为页面读者，我想 HTML 注释不被发送，这样模型不会把 `<!--?lit$29506216$-->` 这类渲染标记回显到译文里。
4. 作为页面读者，我想剥离后只剩空白的宿主不发起请求，这样页面上不会出现一个翻译了空内容的译文节点。
5. 作为页面读者，我想 `<span> </span>`、`<div><br></div>`、只含空白字符的块都不产生译文节点，因为它们没有可翻译的内容。
6. 作为页面读者，我想 `&nbsp;`、`&ensp;` 这类实体解码后为空白的内容同样被判为空，不产生请求。
7. 作为页面读者，我想零宽字符（U+200B–U+200D）单独构成的块也被判为空，不产生请求。
8. 作为页面读者，我想只含媒体标签（图片、视频等）的块不产生请求，因为媒体数据本就不参与翻译。
9. 作为页面读者，我想脚本里的中文不再影响宿主判定，这样「短英文 + 长中文脚本」的段落仍会被翻译，而不是整段被跳过。
10. 作为页面读者，我想纯脚本的块级元素（即使被样式撑出高度）不产生宿主，也不发出空内容的请求。
11. 作为页面读者，我想含脚本的常规段落仍被正常翻译，脚本被删掉而正文完整保留、语序不变。
12. 作为页面读者，我想 `<template>` 里未挂载的内容（含其中属性、媒体数据、脚本）不进入请求，这样 Reddit 这类站点的组件模板不会泄漏进请求内容。
13. 作为页面读者，我想译文节点的外观、位置、流式预览、错误提示与本次改动前逐字节一致。
14. 作为页面读者，我想进度徽标的分母只统计真正会发请求的宿主，这样百分比不会被永远不发的空宿主拖住。
15. 作为页面读者，我想剥离后为空的宿主不占用并发槽，这样有效宿主的请求不会被空请求挤后。
16. 作为页面读者，我想空宿主不写入「已处理」登记，这样页面后来自行填充了内容时它仍能被翻译。
17. 作为页面读者，我想翻译会话的其余行为（还原、重扫、失败只影响单宿主、短文本缓存、会话重用链）零变化。
18. 作为扩展维护者，我想剥离清单与资格判定的排除清单是同一份定义，这样将来改一处不会漏另一处。
19. 作为扩展维护者，我想剥离清单是单一常量，新增标签只改一处。
20. 作为扩展维护者，我想「空」的判定复用仓库既有的空白字符口径，不在第二处重新定义什么算空白。
21. 作为扩展维护者，我想输出侧净化闸门本次零改动，把改动面限制在输入侧。
22. 作为扩展维护者，我想页面真实 DOM 保持零写入（快照在克隆子树上进行），译文节点与进度徽标仍是唯一被注入页面的东西。
23. 作为扩展维护者，我想有变异可验证的用例：清单删一项、空白判定改窄、两处清单不同源，都必须有用例转红。
24. 作为扩展维护者，我想本次改动有端到端的守门用例：直接断言端口 `start` 消息里的请求内容不含脚本与注释。
25. 作为扩展维护者，我想文档同步落在独立票据里，用例数按实测更新。

## Implementation Decisions

- **D1 剥离清单（非渲染标签）**：`script`、`style`、`iframe`、`template`、`noscript`、`link`、`meta`、`base`，共 8 个。快照时删除元素及其整棵子树。清单定义在宿主发现模块内的单一常量处，与既有的媒体占位清单、控件换名清单并列。
- **D2 `<template>` 的处理就是删元素**：`<template>` 的子内容存放在它的 `content` 文档片段上，不在普通子孙链上——`querySelectorAll` 与文本收集的 `TreeWalker` 都遍历不到，而 `innerHTML` 序列化会输出它。删除该元素即连带 `content` 一并消失，不需要为 `content` 单独写一遍遍历。这一条是本功能对本次报错最直接的修复。
- **D3 HTML 注释一并删除**：注释不渲染、会进入请求内容，且实测被模型回显后输出侧净化也删不掉（净化只删元素）。快照里用注释节点遍历收集后删除。只在输入侧删；输出侧净化不动（D7）。
- **D4 剥离与资格判定同源**：资格判定收集宿主文本时的排除范围，由「仅 `pre`/`code` 子树」扩为「`pre`/`code` 子树 + 非渲染标签清单」，与快照删除用同一份常量。主要理由是脚本里的中文会进入汉字占比计算（连带后果一）；次要理由是纯脚本元素在被样式撑出高度时会被判为合格宿主（连带后果二的前半）。
- **D5 剥离后为空则不产生条目**：快照在剥离、媒体子树清空、控件换名、属性删除全部完成之后，取克隆子树的文本内容；若整串只由空白构成，快照返回空字符串，宿主发现出口丢弃该候选。判空的对象是**剥离后的实际发送内容**，与资格判定（看的是「除 `pre`/`code` 与剥离清单之外的文本」）覆盖范围不同，两者分工不重复：判空兜住资格判定覆盖不到的偏差，例如被媒体步骤清空子树的块。
- **D6 空白的定义与 sanitize 同口径**：复用输出侧既有的空白字符口径——`\s` 加零宽 U+200B–U+200D（`\s` 已含 NBSP、U+2000–U+200A、U+3000、U+FEFF）。实现为文本工具模块里的纯函数（宿主发现模块已依赖该模块），注释里指明与输出侧同源；输出侧模块本次不动。
- **D7 输出侧零改动**：净化闸门不新增禁令、不删注释。输入侧删掉后模型基本不会再产生这些内容；保持改动面最小，输出侧的任何收紧留作将来的独立决定。
- **D8 判空落点在宿主发现出口**：只有该出口拿得到剥离后的内容。落在这里的直接好处是下游零改动——不产生条目即不建译文节点、不占并发槽、不计入进度徽标的分母与括号、不写「已处理」登记；翻译会话、并发池、徽标、背景页、配置页、选项页都无需改动。
- **D9 空宿主不写「已处理」登记**：页面后来自行填充内容时，下一轮重扫仍会评估该宿主。每轮重扫本来就会做一次快照，开销与现状相同。
- **D10 页面真实 DOM 零写入**：剥离与判空都作用在克隆子树上，与既有快照语义一致。
- **D11 零痕迹**：代码、测试、文档不出现真实端点、密钥、厂商模型名；测试数据一律假值。

## Testing Decisions

- 好测试的标准沿用仓库口径：只断言外部可观察行为——快照返回的字符串、宿主发现出口的条目数与条目内容、端口 `start` 消息的载荷，不断言内部实现（不检查常量、不检查遍历顺序）。
- **接缝一（纯函数，既有）**：宿主发现模块的工厂注入接缝，用例沿用既有 jsdom 夹具（内联样式驱动 display + 几何桩）。承载剥离清单逐项、`<template>` 的 `content` 随之消失、注释删除、判空各空白形态、脚本内中文不影响判定、纯脚本容器不产生条目、含脚本段落仍成宿主且发送内容只剩正文。
- **嵌套深度不限是覆盖要求，不是样例选择**：剥离靠一次递归遍历完成，因此用例必须把待删内容放在宿主内**任意多层**包裹的最内层（层数只是构造手段，规格不规定具体层数，也不把层数当作断言对象），空壳判空同样要在任意深度的包裹链上成立。写成固定层数会让「只走一层或两层」的实现只要样例恰在其覆盖范围内就不转红，用例因此失去承力。
- **接缝二（文本工具，既有）**：空白判定的纯函数用例，承载各类空白与零宽字符、以及「有实质字符则不为空」的边界。
- **接缝三（整页集成，既有）**：整页沙箱 + 单宿主请求端口替身，断言端口 `start` 消息里的请求内容不含脚本与注释、判空宿主不发请求且不进徽标分母。这是最高的接缝，也是本功能对用户可见承诺的直接守门；同样要求覆盖任意深度的嵌套。
- **变异验证点**：从剥离清单里删掉一项（如 `script`）→ 该项用例必须转红；把空白判定收窄为只认空格与制表换行 → `&nbsp;` 与零宽字符用例必须转红；让资格判定的排除清单与剥离清单不同源 → 脚本内中文用例必须转红。
- 先红后绿；全套件绿后由文档票按**实测**用例数更新仓库说明。
- Prior art：`tests/host-discovery.test.js`（快照序列化与净化用例）、`tests/text-utils.test.js`（纯函数边界）、`tests/content-rescan.test.js`（整页沙箱与端口替身）。

## Out of Scope

- 输出侧净化闸门的任何改动：不新增禁令、不删注释、不收紧（D7）。
- 页面真实 DOM 的任何修改。
- 宿主发现的既有语义改动：硬跳过选择器对 `contenteditable=""`、`contenteditable="plaintext-only"`、大写 `TRUE` 等字面不匹配的现状，以及 `aria-hidden="false"` 的现状，均保持不动。
- `textarea`、`select`、`option`、`object`、`math`、`form` 等有可见文本或未定论的标签，本次不纳入剥离清单（现状保持）。
- SVG/canvas/video/audio 的备用文本在资格判定里计入、在快照里被媒体步骤清空的既有偏差：由判空兜住（丢弃该宿主），不做「保留这些文本」的反向处理。
- 已翻宿主内追加内容的重翻（既有已知盲区）。
- 性能优化：快照本来每轮都会做，本次不改变复杂度。

## Further Notes

- 报错来源：用户实测 Reddit 页面，宿主内的 `<faceplate-loader><script>SML.load([...], 'zh-CN/', 'auto');</script></faceplate-loader>` 进入请求内容。同一段在输出侧被净化剥掉，因此「页面上看不到，模型却已经收到」。
- 术语：本功能引入词条「非渲染标签」（Non-rendered Tags）——不渲染可见内容的标签，`noscript` 仅在脚本被禁用时渲染（本扩展运行时不可能），`template` 的内容仅在站点脚本把它搬进文档或声明式 shadow DOM 挂载时渲染（那一刻元素本身已不在 DOM 里）。宿主词条补一句：快照时删除非渲染标签及其整棵子树，剥离后内容为空的候选不产生条目。
- 决策记录：`docs/adr/0005-per-host-request.md` 追加 Evolved 段（宿主即请求的请求内容里，非渲染标签与注释被剔除，剥离后为空的宿主不发起请求）。
- 与既有文档的关系：本功能收紧「宿主」词条中「快照 = 标签名与文本」的描述——不是所有标签名与文本都进请求，非渲染标签连子树一起剔除。
- 风险：剥离清单若漏项，同一种成因会复现（不可见内容进入请求内容）。清单只有一处定义，将来新增标签只改一处，并有逐项用例锁定。
