# 01: 剥离非渲染标签与剥离后判空

**What to build:** 翻译请求里不再出现脚本、样式、框架、模板、注释这些不渲染的内容，剥离后只剩空白的宿主也不发起请求。做完这一个切片，打开一个内含 `<script>SML.load([...])</script>` 的页面点翻译：译文照常出现，而端点收到的请求内容里没有那段脚本；一个只含 `<span> </span>` 或只含图片的块既不产生译文节点，也不占并发槽，也不进进度徽标的分母。脚本里的中文不再让「短英文 + 长中文脚本」的段落被整块跳过。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 宿主发现模块内新增单一常量：非渲染标签清单 = `script, style, iframe, template, noscript, link, meta, base`（与既有的媒体占位清单、控件换名清单并列，同一处定义）。
- [x] 快照序列化在删除 `.translate-node` 之后、媒体子树清空之前，新增一步：删除清单内元素及其整棵子树。删除 `<template>` 元素即连带它的 `content` 一并消失（不为 `content` 单独写遍历）。
- [x] 快照序列化新增一步：删除 HTML 注释节点（注释节点遍历收集后删除）。注释不渲染，且输出侧净化只删元素、删不掉注释，故在输入侧删。
- [x] 资格判定收集宿主文本时的排除范围，由「仅 `pre`/`code` 子树」扩为「`pre`/`code` 子树 + 非渲染标签清单」，**与快照删除用同一份常量**（同源，不得各写一份）。
- [x] 剥离后判空：快照在剥离、媒体子树清空、控件换名、属性删除全部完成之后，取克隆子树的文本内容；整串只由空白构成时快照返回空字符串。
- [x] 空白口径与输出侧既有净化同源：`\s` 加零宽 U+200B–U+200D（`\s` 已含 NBSP、U+2000–U+200A、U+3000、U+FEFF），实现为文本工具模块里的纯函数并在注释里指明同源；HTML 实体经文本内容取用后已解码，不做实体层特判。
- [x] 宿主发现出口丢弃快照为空的候选：不产生条目、不建译文节点、不占并发槽、不计入进度徽标的分母与括号、不写「已处理」登记（页面后来填充内容时下一轮重扫仍会评估它）。
- [x] 页面真实 DOM 零写入：剥离与判空都作用在克隆子树上。
- [x] 用例（宿主发现接缝，沿用既有 jsdom 夹具）：非渲染标签逐项被删除；`<template>` 删元素后其 `content` 内的文本、属性、媒体数据、脚本都不出现在快照里；HTML 注释不出现在快照里；`<span> </span>`、`<div><br></div>`、`<div><img src=x></div>`、纯空白文本各形态（含 `&nbsp;`、`&ensp;` 解码后、零宽字符）的快照为空串且不产生条目；纯脚本容器（被样式撑出高度）不产生条目；脚本里的中文不影响资格判定（短英文段落仍成宿主）；回归：含脚本的常规段落仍成宿主，且快照里只剩正文、语序不变。
- [x] 用例（宿主发现接缝）：**嵌套深度不限**——宿主内逐层包裹任意多层元素，把 `script`、`noscript`、`template`、HTML 注释放在最内层，快照仍不含这些内容且正文保留。层数只是构造手段，不是规格内容：用例按循环逐层加深地构造，断言的是「任意深度都被剥离」。
- [x] 用例（宿主发现接缝）：**嵌套深度不限的空壳判空**——宿主内逐层包裹任意多层元素、最内层只有空白文本时，宿主发现出口不产生条目（整条空壳链算空）。
- [x] 用例构造注意：夹具外层不得用 `<p>` 包裹块级子元素（HTML 解析会拆分），且内层块级元素会命中常见块查询而使条目落在更深的叶子块上；断言应写在「全部条目的快照串起来」上，不要假定只有一个条目。
- [x] 用例（文本工具接缝）：空白判定纯函数的各类空白与零宽字符为真，含任一实质字符为假。
- [x] 变异验证：从剥离清单里删掉一项（如 `script`）→ 该项用例转红；把空白判定收窄为只认空格与制表换行 → `&nbsp;`/零宽字符用例转红；让资格判定的排除清单与剥离清单不同源 → 脚本内中文用例转红。
- [x] `npm test` 全绿（既有用例零改动、零删除；不碰输出侧净化模块、不碰会话/并发池/徽标/背景页/配置页）。
- [x] 零痕迹：代码与测试不出现真实端点、密钥、厂商模型名；测试数据一律假值。

## Comments

- 决策来源：spec `.scratch/feed-strip-non-rendering/spec.md` 的 D1–D6、D8–D11，以及 Testing Decisions 的接缝一与接缝二。
- 报错来源（用户实测）：Reddit 评论块内的 `<faceplate-loader><script>SML.load([...], 'zh-CN/', 'auto');</script></faceplate-loader>` 进入请求内容；同一段在输出侧被净化剥掉，因此「页面上看不到，模型却已经收到」。
- 三处成因（本票全修）：① 硬跳过选择器经 `closest` 只判断候选元素自身及其祖先，宿主一旦被接受就不再向下访问，其内部的 `script` 从未接受过该判断；② 资格判定收集文本时只排除 `pre`/`code` 子树；③ 快照序列化的剥离步骤清单里没有这些标签。
- `<template>` 的成因单独记：它的内容存放在 `content` 文档片段上，不在普通子孙链上——元素遍历与文本收集的 `TreeWalker` 都到不了，而 `innerHTML` 序列化会输出它。删元素即可一并解决。
- 判空与资格判定分工不重复：资格判定看的是「除 `pre`/`code` 与剥离清单之外的文本」，判空看的是「剥离后的实际发送内容」；后者能兜住资格判定覆盖不到的偏差（如被媒体步骤清空子树的块）。
- 本票交付一个可独立验证的纵切片：模块改动与它的全部用例同票落地，不留无消费者的行为。
- 深度覆盖是规格要求而非样例选择：剥离靠一次递归遍历完成，任意深度都必须覆盖；写成固定层数会让「只走一层或两层」的实现只要样例恰在其覆盖范围内就不转红。
