# 02: 端口请求内容的端到端守门

**What to build:** 把本次承诺锁在用户真正看到的那一层——模型收到的字符串。做完这一个切片，整页沙箱里跑一次翻译，直接断言发给背景页的 `start` 消息里的请求内容不含脚本、不含注释；剥离后为空的宿主既不发起请求（端口连接数不变），也不计入进度徽标的分母。这样将来任何一层（快照、判空、会话装配）被改动而让不可见内容重新进入请求，用例立刻转红。

**Blocked by:** 01（剥离非渲染标签与剥离后判空）

**Status:** resolved

- [x] 用例（整页集成接缝，沿用既有整页沙箱 + 单宿主请求端口替身）：页面含脚本、注释、以及一段正常英文正文 → 断言 `start` 消息的请求内容含正文、不含脚本文本、不含注释。
- [x] 用例：`<template>` 元素（含其中的属性、媒体数据、脚本）不在请求内容里。
- [x] 用例：只含空白或只含媒体标签的块 → 不发起请求（端口连接数为 0，或与正文宿主数相等），且进度徽标分母只统计真正会发请求的宿主。
- [x] 用例：脚本里的中文不影响资格判定 → 短英文段落仍发出请求，请求内容只剩正文。
- [x] 用例：**嵌套深度不限**——宿主内逐层包裹任意多层元素、最内层放 `script`、`noscript`、`template`、HTML 注释，另加一段正常英文正文 → 断言 `start` 消息的请求内容不含这些内容、含正文。层数只是构造手段，不是规格内容。
- [x] 用例：判空宿主不写「已处理」登记 → 该块随后被填入正文时，下一轮重扫会为它发起请求。
- [x] 回归：译文节点的外观与位置、流式预览、错误提示、还原清理、重扫行为与本次改动前一致。
- [x] 变异验证：临时让快照把非渲染标签清单置空（或在判空处恒返回非空）→ 本票用例必须转红，随后回滚。
- [x] `npm test` 全绿；本票只新增测试，不改源码（若发现必须改源码才能满足用例，退回票 01 的范围，不在本票夹带）。
- [x] 零痕迹：测试数据一律假值。
