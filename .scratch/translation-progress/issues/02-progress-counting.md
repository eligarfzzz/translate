# 02: 计数接线——分母按档拆分、分子随落定增长、错误括号

**What to build:** 徽标从静态零态变为实时进度。宿主发现出口按翻译优先级档位计数：档 0（正文）与档 1（未标记）计入进度分母，档 2（边缘区域：header/footer/nav/aside 及等效 role）只计入括号内的总数；首轮与重扫共享同一出口，重扫新增宿主时分母与括号同步增长（百分比可因此下降，属预期）。每宿主流落定（定稿 / error 消息 / 连接意外中断 / 空回显「未返回译文」）分子 +1 并向下取整重算百分比；三条失败路径（error 消息 / 空回显 / 连接中断）同时错误数 +1，错误数 > 0 时文案追加 `(<errors>)`，无错误时不显示。净化为空导致的静默移除算落定但不算错误、分子不回退；出错的流也计入分子（进度可达 100%）。落定计数挂在端口流程 settle 的唯一收口上，每宿主恰好一次，不存在第二条计数路径。

**Blocked by:** 01（进度徽标模块与会话生命周期）

**Status:** ready-for-agent

- [ ] 混合档位页面：分母排除边缘档，括号内为全部宿主数（如正文 2 + 边缘 1 → `0% 0/2(3)`）
- [ ] 每宿主落定分子 +1，百分比向下取整（如 1/3 → 33%，全部落定才 100%）
- [ ] error 消息路径：分子 +1、错误括号出现且计数正确；无错误时错误括号不显示
- [ ] 重扫新增宿主后分母与括号同步增长
- [ ] 净化为空的静默移除：算落定、不算错误、分子不回退
- [ ] 出错的宿主同样计入分子，含错误时进度仍可达 100%
- [ ] 沙箱集成测试覆盖上述分支，沿用 content-sandbox 夹具（可控时序 mock 端口），不改既有用例
- [ ] `npm test` 全绿
