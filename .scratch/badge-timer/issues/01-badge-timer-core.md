# 01: 徽标计时——全落定后追加 `<主内容>(<全内容>)s`，及时间源注入

**What to build:** 进度徽标在**全部已发现宿主（含档 2 边缘区域）都落定之后**，于原文案末尾追加一段耗时读数：括号外是**主内容（档 0/1）全部落定**那一刻的已用秒数，括号内是**全部宿主落定**那一刻的已用秒数，单位为秒（`100% 5/5(7)(1) 60(80)s`）。取数只在宿主落定的那一刻发生——**不引入任何定时器**；新段落被重扫发现时读数立刻撤下（避免把过时旧值当当前耗时），新段落翻完再带着继续累计后的新读数回来。时间源按本仓既有做法**显式注入**（`env.now`），真实环境是 `Date.now`，测试沙箱接手动时钟，使精确秒数可断言。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] `createProgressBadge({ doc, now })` 新增 `now` 依赖（返回毫秒的函数）；`now()` 差值按 `Math.floor` 换算为秒（与百分比同口径，不显示小数）。
- [x] 计时起点 = `show()` 被调用的时刻；`remove()` 清零全部新增状态（两个定格值、全档位落定计数），下次 `show()` 重新起算。
- [x] `addHosts(translatable, all)`：新宿主解冻对应集合——`translatable > 0` 时主内容与全内容两个定格值都作废；`translatable === 0 && all > 0` 时**只**作废全内容定格值（主内容时间保持旧值）。
- [x] `settled(counted, errored)`：新增全档位落定计数（每调用一次 +1）；主内容集合满足 `total > 0 && done === total` 时定格主内容秒数；全档位集合满足 `totalAll > 0 && settledAll === totalAll` 时定格全内容秒数。
- [x] `format()`：仅当 `totalAll > 0 && settledAll === totalAll` 时追加 ` <主>(<全>)s`——**直接空格**分隔，紧跟在错误括号之后，单位只写一次；主内容宿主数为 0 的页面括号外写 `0`。零宿主页面（`totalAll === 0`）永不出现时间后缀。
- [x] **不引入任何计时器**：不调 `setTimeout`/`setInterval`，只在 `show`/`addHosts`/`settled` 触发的渲染里计算文案——"调度收敛后无在途计时器"的既有观测继续成立。
- [x] `src/content.js`：把 `env.now` 透传给徽标工厂；`settleHost` 的调用签名与计数口径**不动**。
- [x] `src/content-loader.js`：注入 `now: () => Date.now()`。
- [x] `tests/helpers/content-sandbox.js`：注入 `now: () => clock.now`（放在既有的手动时钟接入段旁，同一理由：会话的时间读数由沙箱时钟精确控制）。
- [x] **既有断言分两类处理，任何一条都不得放宽**：
  - 全部落定断言的期望值追加 ` <主>(<全>)s`（秒数按沙箱时钟在该断言时刻的读数；这些用例此前未推进时钟，应为 `0(0)s`）。清单：`混合档位页分母排除边缘档…` 中**边缘档落定后**那条 `100% 2/2(3)`；`每宿主流落定分子 +1…` 的 `100% 3/3(3)`；`error 消息路径…` 的 `100% 3/3(3)(1)`；`连接意外中断计错误…` 的全部落定条与**紧随其后的迟到消息条**（均为 `100% 3/3(3)(1)`）；`空回显未返回译文…` 的 `100% 3/3(3)(1)`；`边缘档宿主失败只进错误括号…` 的 `100% 2/2(3)(1)`；`重扫新增宿主后分母与括号同步增长…` 的 `100% 1/1(1)` 与二波 `100% 2/2(3)`。
  - 在途断言（断言时仍有宿主未落定）一律**逐字不动**：包括 `混合档位页…` 中**边缘档落定前**那条与上一条文本完全相同的 `100% 2/2(3)`（这是本特性最直接的守门），以及全部 `0% …`、`33% …`、`50% …`、`66% …` 形态的断言。
- [x] 新增用例（全部在 `tests/content-rescan.test.js`，**必须推进沙箱时钟使秒数非零**，否则"定格/解冻"不可观测）：
  - [x] 主内容与全内容两个秒数不同（如主内容 12s 落定、边缘 60s 落定 → `12(60)s`），证明括号外定格在**主内容**落定时刻而非全内容落定时刻。
  - [x] 全落定后再推进时钟（如 `advance(5000)`）：文案逐字不变、`clock.pending() === 0`——证明无定时器、读数不漂移。
  - [x] 动态插入新段落 → 重扫发现 → 时间后缀消失（其余文案按既有口径变化）→ 新宿主落定 → 时间后缀回来且**继续累计**（新值大于旧值）。
  - [x] 只新增边缘档宿主：括号外保持旧定格值，括号内更新为更大的秒数。
  - [x] 还原后再翻译：时间从 0 重新起算（不残留上一次的读数）。
  - [x] 无主内容宿主的页面（只有 header/nav 一类边缘档宿主）：全落定后括号外为 `0`。
  - [x] 零宿主页面：文案保持 `0% 0/0(0)`，永不出现时间后缀。
- [x] 先红后绿证据：新增/改写的断言在新实现落地前必须实际转红（旧实现在全部落定后不输出时间后缀），改后转绿；留下可复述的断言输出与命令退出码。
- [x] `npm test` 全绿（lint + node:test）；除本票明确要求的输出后缀追加外，不得改动任何既有行为断言的语义。

## Comments

- 用户决策（本票相关）：格式 `60(80)s`（括号外主内容、括号内含导航/header 的全内容，单位秒）；**时间只在全部翻完才出现**；**新段落开始时隐藏，翻完再显示**；时间与错误括号之间用**直接空格**分隔（不用分隔符）。
- 起点的语义：用户未要求"暂停/继续"，故起点固定在 `show()`、隐藏期间照常累计；`0(0)s` 的极短会话是正常输出。
- 为什么不用定时器：既有的"调度收敛后无在途计时器"不变量被大量用例观测；秒表式刷新会让徽标在整个会话期持续重渲染，而用户要的是耗时读数。
- 空主内容集合按 `0` 显示：避免引入第三态（`-`），且"空集在起点即完成"与百分比口径（`total === 0` 时按 0）自洽。
