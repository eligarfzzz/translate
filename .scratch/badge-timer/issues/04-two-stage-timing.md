# 04: 两段式耗时读数——正文落定先给 `<主>s`，全内容落定补成 `<主>(<全>)s`

**What to build:** 显示规则修订（用户要求）：现在只在**全部宿主都落定**后才一次性给出 `60(70)s`，用户要的是**正文一翻完就读到正文耗时**。改成两段——正文（档 0/1）首次全部落定时先给 ` 60s`（无括号）；边缘区域（档 2）也落定后补成 ` 60(70)s`，括号外仍是那个 60，不重算。顺带把票 03 留下的注释缺陷（R9）改直白：`${mainSecs ?? 0}` 是活兜底、`${allSecs ?? 0}` 才是当前代码路径走不到的兜底。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `src/content-progress.js` 的 `format()`：正文读数在正文定格值已存在（`mainSecs !== null`）时显示 ` ${主}s`；括号部分仍只在 `totalAll > 0 && settledAllCount === totalAll` 时补上（`(${allSecs ?? 0})`），单位 `s` 只写一次。
- [ ] **不引入新状态**：`mainSecs` 的定格与解冻逻辑一个字不动（它本来就精确等于"正文曾全部落定、且此后未被解冻"）；`settled()` / `addHosts()` / `remove()` 不需要为两段式做任何改动。
- [ ] 注释按 spec D10 改成直白措辞：`${mainSecs ?? 0}` 是**活兜底**（无主内容宿主的页面里它恒为 `null`，兜出的 `0` 是 D4 的要求），`${allSecs ?? 0}` 是**当前代码路径走不到**的兜底、纯防将来改显示条件。不得再出现"今日不可达"这类把两者混为一谈的说法（评审已复现：只含边缘档宿主的页面实测 `0% 0/0(2) 0(3)s`，证明前者是活分支）。
- [ ] 既有断言**只许改这 3 条**（正文已满 100%、原期望无时间后缀者；行号是 HEAD `59a5e40` 时的定位，编辑后漂移，请按字面量定位）：
  - `tests/content-rescan.test.js:659` `"100% 2/2(3)"` → `"100% 2/2(3) 0s"`
  - `tests/content-rescan.test.js:914` `"100% 2/2(3)"` → `"100% 2/2(3) 12s"`
  - `tests/content-rescan.test.js:998` `"100% 1/1(3)"` → `"100% 1/1(3) 4s"`
  其余断言（正文未满 100%、以及已带时间后缀者）逐字不动。不得放宽、不得删除任何断言。
- [ ] 新增用例（秒数必须非零，否则两阶段不可区分）：
  - [ ] 正文 12s 全部落定、边缘在途 → `100% 2/2(3) 12s`（只有正文读数、无括号）
  - [ ] 时钟走到 60s、边缘落定 → `100% 2/2(3) 12(60)s`（补括号、括号外仍是 12）

## Comments

- 决策来源：spec 的 D1 / D2 / D11（§1–§4 已按两段式改写）。
- **D11 的 (a) 是主代理按推荐落的默认值**（用户未就该点表态）：无主内容宿主的页面不进入第一阶段。若要改判 (b)「空集视为起点即完成」，只需在正文显示条件里加 `total === 0 ||`，并把该页面"边缘在途"那条断言从 `0% 0/0(2)` 改成 `0% 0/0(2) 0s`。
- 本票**修订**了票 01 建立的口径（"只在全部落定后显示"）：那是当时的决定，用户看了实测序列后改为两段式。票 01 的验收记录不动（它记录的是当时的口径）。
- R9 并入本票：票 03 新增的注释把"当前代码路径走不到"错误地扩大到 `mainSecs`，评审发现、主代理已复现。同一段注释本票要重写，一并在 D10 的口径下改直白，不再单开票。
- 已知边界（非本票缺陷，不要在实现里"顺手"处理）：新内容出现到读数撤下之间有一个约 0.5s 的重扫防抖窗口，这是 spec 刻意接受的；隐藏期间时间照常累计，起点固定在 `show()`。
