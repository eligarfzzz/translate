# Spec: 进度徽标计时——全部落定后追加 `<主内容>(<全内容>)s`

## Problem Statement

- 徽标只回答"翻了多少"（`<pct>% <done>/<total>(<totalAll>)`），不回答"花了多久"。用户想知道本次翻译的总耗时，以及**只算正文**的耗时——正文翻完即可开始读，导航/页脚/侧栏（边缘区域）什么时候翻完并不影响阅读。
- 现有计数口径已经天然具备这两个集合（分母 `total` = 档 0/1 主内容，括号 `totalAll` = 含档 2 的全量），缺的只是时间：两个集合各自"全部落定"的时刻。
- 直接显示"当前已用秒数"需要常驻定时器持续刷新，会破坏既有不变量（调度收敛后无在途计时器，测试与实现都依赖它），并让徽标在整个会话期持续重渲染。而用户要的是**耗时读数**，不是秒表动画。

## Solution

### 1. 显示时机：只在"全部落定"后显示，新内容出现即隐藏

- 显示条件（唯一）：**已发现的全部宿主（含档 0/1/2）都已落定**，且本次会话至少发现过 1 个宿主（`totalAll > 0`）。
- 隐藏条件：任一新宿主被发现（`addHosts` 收到非零计数）时立刻隐藏；隐藏状态一直持续到再次全部落定。
- 含义：时间后缀是"这一轮干完了"的读数，不是一个还在跑的秒表。页面动态加载新段落 → 读数先撤下（避免显示一个已经过时的旧值），新段落翻完再带着新读数回来。
- 零宿主页面（`totalAll === 0`）永不显示时间——没有任何翻译发生过，`0(0)s` 只会让人困惑。

### 2. 两个数字：主内容落定时刻、全内容落定时刻

格式（追加在原文案末尾，**直接空格**分隔，单位后缀 `s`）：

```
100% 5/5(7)(1) 60(80)s
        └──┬──┘ └──┬──┘
           │       └─ 全部宿主（含边缘区域）落定那一刻，已用 80 秒
           └─ 主内容（档 0/1）全部落定那一刻，已用 60 秒
```

- 两个数字都是**定格值**：在各自集合"全部落定"的那一刻取一次，之后不再随渲染漂移。
- 主内容集合为空（页面只有导航/页脚这类边缘档宿主，`total === 0`）时，括号外按 `0` 显示——空集视为在起点即已完成。不引入 `-` 这类第三态。

### 3. 时间线示例

页面：5 个正文段落（档 0）+ 2 个边缘档宿主（header/nav）= 7 个可翻对象。

| 时刻 | 事件 | 徽标 |
| --- | --- | --- |
| 0s | 点「翻译」 | `0% 0/5(7)` |
| 12s | 翻完 2 个正文段 | `40% 2/5(7)`（仍在途 → 不显示时间） |
| 60s | 5 个正文段全部翻完 | `100% 5/5(7)`（边缘档仍在途 → 仍不显示时间） |
| 80s | 边缘档也翻完 | `100% 5/5(7) 60(80)s` |
| 90s | 页面动态插入 3 个新正文段，重扫发现 | `62% 5/8(10)`（读数撤下；分母 5→8、括号 7→10） |
| 95s | 新段落翻完 | `100% 8/8(10) 95(95)s`（主内容时间一并解冻并重新定格） |

### 4. 解冻规则按集合分别判定

- 新宿主属于**主内容**（`addHosts` 的 `translatable > 0`）→ 两个数字都解冻，重新落定时各自更新。
- 新宿主**只有边缘档**（`translatable === 0`、`all > 0`）→ 括号外保持旧定格值（正文确实早就翻完了，这个事实没变），括号内解冻更新。

### 5. 不引入任何定时器

只在宿主落定的那一刻读一次时间（`now()` 差值），**不装 `setInterval`**：

- 徽标不因时间流逝而持续重渲染；会话静止时无在途计时器这一既有不变量继续成立（"调度收敛"的观测手段不受影响）。
- 时间源**显式注入**：`env.now`（返回毫秒的函数）。真实环境是 `() => Date.now()`；测试沙箱接手动时钟 `() => clock.now`，使 `60(80)s` 这样的精确秒数可断言。

### 6. 秒数向下取整

与百分比口径一致（`Math.floor`）：59.9 秒显示 `59`。不显示小数、不做四舍五入。

## User Stories

- 作为用户，我想知道这次翻译总共花了多久，以便判断是不是网络/服务慢。
- 作为用户，我想知道**正文**多久翻完，因为正文一好我就能开始读，不必等导航和页脚。
- 作为用户，页面动态加载出新内容时，我不想看到一个已经过时的旧时间被当成"当前耗时"。
- 作为用户，我不想看到时间数字不停地跳——它该是一个读数，不是秒表。

## Implementation Decisions

- **D1 显示条件**：`totalAll > 0 && settledAllCount === totalAll`（`settledAllCount` 为全档位落定计数，新增）。
- **D2 两个定格时刻**：主内容集合首次满足 `total > 0 && done === total` 时定格括号外秒数；全档位集合首次满足 `totalAll > 0 && settledAllCount === totalAll` 时定格括号内秒数。
- **D3 起点**：`show()` 被调用的时刻（即点「翻译」）。`remove()` 清零全部状态（含两个定格值与全档位计数），下次 `show()` 重新起算——与既有"再次翻译回到零态"的行为一致。
- **D4 空主内容集合**：括号外按 `0`。
- **D5 文案摆放**：直接空格追加在错误括号之后（`(1) 60(80)s`），不加分隔符、不加标签、单位只写一次 `s`。
- **D6 无定时器**：只在 `settled` / `addHosts` / `show` 触发的渲染里计算文案。
- **D7 注入接缝**：`createProgressBadge({ doc, now })`；`src/content.js` 透传 `env.now`；`src/content-loader.js` 注入 `() => Date.now()`；`tests/helpers/content-sandbox.js` 注入 `() => clock.now`（紧邻既有的"手动时钟接入注入文档所属 window"段，同一理由：让会话的时间读数可被测试精确控制）。
- **D8 不改计数口径**：百分比、分子分母、`<totalAll>`、错误括号的语义一个字不动；`settleHost` 的调用签名也不动（`settled(counted, errored)` 内部新增全档位计数即可——落定收口已保证每宿主恰好一次）。
- **D9 不加 ADR**：这是既有领域概念（进度徽标）的展示口径扩展，不改变架构接缝；语义写进 `CONTEXT.md` 即可。
- **D10 两个 `?? 0` 兜底性质不同**（票 03 评审发现，措辞以票 04 为准）：`${mainSecs ?? 0}` 是**活分支**——主内容集合为空（`total === 0` 且 `totalAll > 0`）时 `mainSecs` 恒为 `null`，而显示条件照样成立，此时兜出的 `0` 正是 D4 要求的「空集视为起点即完成」；`${allSecs ?? 0}` 才是**今日不可达的死分支**（显示条件已蕴含 `allSecs !== null`），纯防未来改写。两者的注释不得合并成同一句「即将不可达」。

## Testing Decisions

- 既有断言分两类，**不许放宽**：
  - **在途断言**（该时刻仍有宿主未落定）→ 文案中不得出现时间后缀，期望值逐字不动。
  - **全部落定断言** → 期望值追加 ` <主>(<全>)s`；这些用例此前未推进沙箱时钟，秒数应为 `0(0)s`（以沙箱时钟在该断言时刻的真实读数为准）。
- 既有徽标用例里有一对**文本完全相同但语义相反**的断言（混合档位用例中的两条 `100% 2/2(3)`）：第一条在边缘档**仍在途**时必须逐字不动，第二条在边缘档**已落定**后必须带上时间后缀——这两条是本特性最直接的守门。
- 新增用例必须让秒数**非零**（推进沙箱时钟后再落定），否则"定格"与"解冻"不可观测：`0(0)s` 无法区分"定格了"与"没定格"。
- 需要覆盖的新场景：主内容先落定、边缘后落定（两个数字不同）；全落定后时钟继续走，文案不变（证明无定时器、无漂移）；新段落出现 → 隐藏 → 再落定 → 继续累计；只新增边缘档 → 括号外保持旧值；还原后再翻译重新起算；无主内容宿主的页面括号外为 0；零宿主页面永不显示时间。
- 断言只落在可见结果（`badge.textContent`）与调度观测（`clock.pending() === 0`），不断言内部实现。

## Out of Scope

- 暂停/继续计时、毫秒精度、倒计时或预计剩余时间。
- 时间历史、多次翻译的对比、把耗时写入日志或落盘。
- 按宿主/按档位分别列出耗时；时间格式可配置；时长的国际化文案。
- 修改百分比、分子分母、`<totalAll>`、错误括号的任何语义。
- 新增 ADR。

## Further Notes

- 徽标样式（内联硬编码常量）不变，时间后缀只是 `textContent` 的一部分。
- 「新内容出现 → 隐藏」的触发点是**重扫发现新宿主**（防抖到期后），不是 DOM 变化的那一刻——因此新内容出现到读数撤下之间有一个防抖窗口（与"何时开始翻译新内容"同一个窗口），这是刻意接受的。
- 隐藏期间时间照常累计：起点固定在 `show()`，不会因为隐藏而过期。
