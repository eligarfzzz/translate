# Spec: 进度徽标计时——正文落定先给 `<主内容>s`，全内容落定再补成 `<主内容>(<全内容>)s`

## Problem Statement

- 徽标只回答"翻了多少"（`<pct>% <done>/<total>(<totalAll>)`），不回答"花了多久"。用户想知道本次翻译的总耗时，以及**只算正文**的耗时——正文翻完即可开始读，导航/页脚/侧栏（边缘区域）什么时候翻完并不影响阅读。
- 现有计数口径已经天然具备这两个集合（分母 `total` = 档 0/1 主内容，括号 `totalAll` = 含档 2 的全量），缺的只是时间：两个集合各自"全部落定"的时刻。
- 但**让用户等边缘区域**是没必要的：正文一翻完，正文耗时就已经是个确定的事实。读数分两步给——正文落定先给 `60s`，边缘区域也翻完再补成 `60(70)s`——用户不必为了看到正文耗时去买单最慢的边缘宿主。
- 直接显示"当前已用秒数"需要常驻定时器持续刷新，会破坏既有不变量（调度收敛后无在途计时器，测试与实现都依赖它），并让徽标在整个会话期持续重渲染。而用户要的是**耗时读数**，不是秒表动画。

## Solution

### 1. 显示时机：正文落定先给读数，全内容落定再补括号

- **第一阶段（正文读数）**：主内容集合（档 0/1）首次全部落定时出现——判据就是正文定格值已存在（该集合曾满足 `total > 0 && done === total` 且此后未被解冻）。文案形如 ` 60s`，没有括号。
- **第二阶段（补括号）**：**已发现的全部宿主（含档 0/1/2）都已落定**且至少发现过 1 个宿主（`totalAll > 0`）时，补成 ` 60(80)s`；括号外仍是第一阶段定格的 60，不重算。
- 撤下 / 回退：
  - 新宿主的档位含**主内容**（`addHosts` 的 `translatable > 0`）→ 正文读数解冻，整个时间后缀撤下（连括号外也不显示），直到正文再次全部落定。
  - 只新增**边缘档**宿主 → 括号外保持旧定格值（正文确实早就翻完了，这个事实没变），只把括号撤下、退回第一阶段形态 ` 60s`；该宿主翻完后补回括号。
- 含义：正文一翻完就能读到"正文花了多久"，不必为最慢的边缘宿主买单；括号是"这一轮全干完了"的补记。读数仍是**定格值**，不是还在跑的秒表；隐藏期间时间照常累计（起点固定在 `show()`）。
- 零宿主页面（`totalAll === 0`）永不显示时间——没有任何翻译发生过，`0s` / `0(0)s` 只会让人困惑。
- 无主内容宿主的页面（`total === 0`）不进入第一阶段，见 D11。

### 2. 两个数字、两个阶段：主内容落定时刻、全内容落定时刻

格式（追加在原文案末尾，**直接空格**分隔，单位后缀 `s`）。

第一阶段——只有正文读数，没有括号：

```
100% 5/5(7)(1) 60s
```

第二阶段——补上括号，括号外仍是第一阶段定格的 60：

```
100% 5/5(7)(1) 60(80)s
        └──┬──┘ └──┬──┘
           │       └─ 全部宿主（含边缘区域）落定那一刻，已用 80 秒
           └─ 主内容（档 0/1）全部落定那一刻，已用 60 秒
```

- 两个数字都是**定格值**：在各自集合"全部落定"的那一刻取一次，之后不再随渲染漂移。
- 主内容集合为空（页面只有导航/页脚这类边缘档宿主，`total === 0`）时，括号外按 `0` 显示——空集视为在起点即已完成。不引入 `-` 这类第三态。这类页面**不进入第一阶段**（见 D11）。

### 3. 时间线示例

页面：5 个正文段落（档 0）+ 2 个边缘档宿主（header/nav）= 7 个可翻对象。

| 时刻 | 事件 | 徽标 |
| --- | --- | --- |
| 0s | 点「翻译」 | `0% 0/5(7)` |
| 12s | 翻完 2 个正文段 | `40% 2/5(7)`（正文未满 → 无时间） |
| 60s | 5 个正文段全部翻完 | `100% 5/5(7) 60s`（边缘档仍在途 → 只给正文读数） |
| 80s | 边缘档也翻完 | `100% 5/5(7) 60(80)s`（补上括号；括号外仍是 60） |
| 90s | 页面动态插入 3 个新正文段，重扫发现 | `62% 5/8(10)`（正文解冻 → 读数整体撤下；分母 5→8、括号 7→10） |
| 95s | 新段落翻完 | `100% 8/8(10) 95(95)s`（重新定格） |

接着上面，看看"全落定后又出现边缘宿主"这一段：

| 时刻 | 事件 | 徽标 |
| --- | --- | --- |
| 100s | 页面又插入 1 个边缘档宿主，重扫发现 | `100% 8/8(11) 95s`（括号撤下，括号外 95 保持） |
| 130s | 该边缘宿主翻完 | `100% 8/8(11) 95(130)s` |

### 4. 解冻规则按集合分别判定

- 新宿主属于**主内容**（`addHosts` 的 `translatable > 0`）→ 两个数字都解冻（正文定格值归 `null`），整个时间后缀撤下；正文再次全部落定时重新定格、重新进入第一阶段。
- 新宿主**只有边缘档**（`translatable === 0`、`all > 0`）→ 括号外保持旧定格值（正文确实早就翻完了，这个事实没变），只把括号撤下、退回第一阶段形态 ` 60s`；该边缘宿主翻完后补回括号。

### 5. 不引入任何定时器

只在宿主落定的那一刻读一次时间（`now()` 差值），**不装 `setInterval`**：

- 徽标不因时间流逝而持续重渲染；会话静止时无在途计时器这一既有不变量继续成立（"调度收敛"的观测手段不受影响）。
- 时间源**显式注入**：`env.now`（返回毫秒的函数）。真实环境是 `() => Date.now()`；测试沙箱接手动时钟 `() => clock.now`，使 `60(80)s` 这样的精确秒数可断言。

### 6. 秒数向下取整

与百分比口径一致（`Math.floor`）：59.9 秒显示 `59`。不显示小数、不做四舍五入。

## User Stories

- 作为用户，我想知道这次翻译总共花了多久，以便判断是不是网络/服务慢。
- 作为用户，我想知道**正文**多久翻完，因为正文一好我就能开始读，不必等导航和页脚。
- 作为用户，页面动态加载出新内容时，我不想看到一个已经过时的旧时间被当成"当前耗时"。
- 作为用户，我不想看到时间数字不停地跳——它该是一个读数，不是秒表。

## Implementation Decisions

- **D1 显示条件（两阶段）**：第一阶段——正文定格值已存在（主内容集合曾满足 `total > 0 && done === total` 且未被解冻）；第二阶段——在满足第一阶段的前提下，`totalAll > 0 && settledAllCount === totalAll` 时补上括号（`settledAllCount` 为全档位落定计数，即票 03 改名前的 `settledAll`）。
- **D2 两个定格时刻**：主内容集合首次满足 `total > 0 && done === total` 时定格括号外秒数（此刻起显示 ` <主>s`）；全档位集合首次满足 `totalAll > 0 && settledAllCount === totalAll` 时定格括号内秒数（此后文案为 ` <主>(<全>)s`）。被解冻后重新落定，按同一规则再定格一次。
- **D3 起点**：`show()` 被调用的时刻（即点「翻译」）。`remove()` 清零全部状态（含两个定格值与全档位计数），下次 `show()` 重新起算——与既有"再次翻译回到零态"的行为一致。
- **D4 空主内容集合**：括号外按 `0`。
- **D5 文案摆放**：直接空格追加在错误括号之后（`(1) 60(80)s`），不加分隔符、不加标签、单位只写一次 `s`；第一阶段没有括号、也只有一个 `s`（`(1) 60s`）。
- **D6 无定时器**：只在 `settled` / `addHosts` / `show` 触发的渲染里计算文案。
- **D7 注入接缝**：`createProgressBadge({ doc, now })`；`src/content.js` 透传 `env.now`；`src/content-loader.js` 注入 `() => Date.now()`；`tests/helpers/content-sandbox.js` 注入 `() => clock.now`（紧邻既有的"手动时钟接入注入文档所属 window"段，同一理由：让会话的时间读数可被测试精确控制）。
- **D8 不改计数口径**：百分比、分子分母、`<totalAll>`、错误括号的语义一个字不动；`settleHost` 的调用签名也不动（`settled(counted, errored)` 内部新增全档位计数即可——落定收口已保证每宿主恰好一次）。
- **D9 不加 ADR**：这是既有领域概念（进度徽标）的展示口径扩展，不改变架构接缝；语义写进 `CONTEXT.md` 即可。
- **D10 两个 `?? 0` 兜底性质不同**（票 03 评审发现）：`${mainSecs ?? 0}` 是**活兜底**——无主内容宿主的页面（`total === 0` 且 `totalAll > 0`）里它恒为 `null`，而第二阶段的显示条件照样成立，兜出的 `0` 正是 D4 要求的「空集视为起点即完成」；`${allSecs ?? 0}` 是**当前代码路径走不到**的兜底（第二阶段条件成立时它必已有值），留着只为将来若改显示条件时不会把字面 `null` 打到页面上。两句注释不得合并成同一句「当前不可达」。
- **D11 无主内容宿主的页面（`total === 0`）不进入第一阶段**：这类页面没有"正文"可报，一点翻译就亮 `0s` 像卡住的读数、而这个 0 不含信息，所以时间只在第二阶段出现，形如 `0% 0/0(2) 0(3)s`（`0` 来自 D4）。这是主代理按推荐落的默认值（用户未就此表态）；若要改判"空集视为起点即完成"，只需在正文显示条件里加 `total === 0 ||`，并把该页面的"边缘在途"断言从 `0% 0/0(2)` 改成 `0% 0/0(2) 0s`（见票 04）。

## Testing Decisions

- 既有断言分两类，**不许放宽**：
  - **正文未满 100%**（该时刻主内容集合仍有宿主在途）→ 文案中不得出现任何时间后缀（连括号外也没有），期望值逐字不动。
  - **正文已满 100%** → 期望值按新规则改写：仍有宿主在途时追加 ` <主>s`（只有正文读数），全部落定时为 ` <主>(<全>)s`。共 **3** 条需要改写：`100% 2/2(3)` 两条（一在边缘在途、一在全部落定）与 `100% 1/1(3)` 一条（只新增边缘档后）。
- 既有的那一对断言（混合档位用例里的两条 `100% 2/2(3)`）在新规则下不再是同一文本，但仍然是本特性最直接的守门：边缘档**仍在途**的那条变成 `100% 2/2(3) 0s`，边缘档**已落定**的那条变成 `100% 2/2(3) 0(0)s`——两者的差别恰好是括号本身。
- 新增用例必须让秒数**非零**（推进沙箱时钟后再落定），否则"第一/第二阶段"不可观测：`0s` 与 `0(0)s` 太容易混淆。
- 需要覆盖的新场景：正文先落定、边缘在途 → 只有 ` <主>s`；边缘随后落定 → 补成 ` <主>(<全>)s`（括号外不动）；正文与边缘**同刻**落定 → 直接 `60(60)s`，不出现中间态；全落定后再插入**边缘**宿主 → 退回 ` <主>s`（括号撤下、括号外保持）→ 该宿主落定后补回括号；全落定后再插入**正文**宿主 → 读数整体撤下；全落定后时钟继续走，文案不变（证明无定时器、无漂移）；还原后再翻译重新起算；无主内容宿主的页面只在第二阶段出现（D11）；零宿主页面永不显示时间。
- 断言只落在可见结果（`badge.textContent`）与调度观测（`clock.pending() === 0`），不断言内部实现。

## Out of Scope

- 暂停/继续计时、毫秒精度、倒计时或预计剩余时间。
- 时间历史、多次翻译的对比、把耗时写入日志或落盘。
- 按宿主/按档位分别列出耗时；时间格式可配置；时长的国际化文案。
- 修改百分比、分子分母、`<totalAll>`、错误括号的任何语义。
- 新增 ADR。

## Further Notes

- 徽标样式（内联硬编码常量）不变，时间后缀只是 `textContent` 的一部分。
- 「新内容出现 → 隐藏」的触发点是**重扫发现新宿主**（防抖到期后），不是 DOM 变化的那一刻——因此新内容出现到读数撤下之间有一个防抖窗口（与"何时开始翻译新内容"同一个窗口），这是刻意接受的。
- 隐藏期间时间照常累计：起点固定在 `show()`，不会因为隐藏而过期。
