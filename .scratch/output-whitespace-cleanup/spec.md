# Spec: 输出侧空白清理与空节点去除——模型回显写入译文节点前的规范化

Status: ready-for-agent

## Problem Statement

模型回显的译文在写入译文节点前，目前只经过两道处理：`stripHostWrapper` 剥最外层 `<html>` 包装并整体 trim（输出侧唯一 trim 处），`sanitizeHtml` 删除 banned 标签与危险属性。**节点级空白与空节点完全没有处理**：

- 译文容器样式 `white-space: pre-wrap`（content-render.js），模型回显的换行、tab、缩进空格会**原样显示**——元素间的换行与缩进变成视觉空行、错位缩进。
- 模型可能回显 `<p></p>`、`<div> </div>`、`<span>\n</span>` 之类空壳节点，原样写入后成为空白块与占位空隙。
- HTML 转义空白（`&nbsp;`、`&#10;`、`&#9;`、零宽 `&#x200B;` 等）解析后即真实空白字符，同样原样上屏。

## Solution

在净化闸门 `sanitizeHtml` 内、危险属性清洗之后、序列化返回之前，新增**空白规范化阶段**：

1. **文本节点清理**（跳过 pre/code 整棵子树）：按文本节点在父容器内的位置判定空白去留——邻接块级边界侧的空白全部删除（块级排版不需要它，pre-wrap 下只会产生视觉空白）；邻接行内内容侧的空白折叠为单个普通空格（防止 `Hello <b>bold</b>` 粘连成 `Hellobold`）。
2. **空元素去除**：自底向上删除无内容元素（无元素子、无清理后非空文本子）；表格结构元素（table/tr/td/th 等）豁免——空单元格常是排版占位，删除会错位塌陷。
3. 清理后为空字符串时，渲染层不再写入空壳译文容器（移除该译文节点）。

## User Stories

1. 作为页面读者，我希望模型回显中元素间的换行与缩进不变成译文节点里的空行和错位缩进，这样译文观感接近正常文本流。
2. 作为页面读者，我希望模型回显的 `<p></p>`、`<div> </div>`、`<span>\n</span>` 空壳节点不写入译文，这样不出现空白块与占位空隙。
3. 作为页面读者，我希望行内相邻译文（如 `Hello <b>bold</b> world`）不因 trim 而粘连，这样单词间保持可读分隔。
4. 作为页面读者，我希望正常句间与词间空格被保留，不被误删。
5. 作为页面读者，我希望 `&nbsp;`、`&#10;`、`&#9;`、`&#x200B;` 等转义空白同样被识别并清理，不留视觉残迹。
6. 作为页面读者，我希望 pre/code 内部的代码换行、缩进与注释原样保留，不被空白清理破坏。
7. 作为页面读者，我希望空表格单元格不因清理而删除，表格结构不错位塌陷。
8. 作为页面读者，我希望模型用 `<br>` 等 void 元素表达的换行仍生效，不被当作空节点误删。
9. 作为页面读者，我希望链式空壳（如 `ul` 中所有 `li` 皆空）被自底向上清干净，不留层层空壳。
10. 作为扩展 owner，我希望清理逻辑全部收敛在净化闸门内、属性清洗之后，banned 标签与危险属性的既有清洗行为完全不变。
11. 作为扩展 owner，我希望流式预览路径不做 trim（防流式期间文字跳闪），trim 只发生在定稿写入。
12. 作为扩展 owner，我希望清理后为空（模型回显全被清空）时译文节点被移除，而不是留下空壳容器。
13. 作为扩展开发者，我希望既有净化测试与渲染测试全部保持绿色，作为回归门槛。

## Implementation Decisions

- **空白字符全集**：`\s`（含空格/tab/换行/回车/`\f`/`\v`）+ NBSP `\u00A0` + 零宽 `\u200B-\u200D` + BOM `\uFEFF`。HTML 实体在 innerHTML 解析后已归一为这些真实字符，无需实体层特判。
- **块级/行内上下文判定**：净化在离线解析文档上进行，取不到页面样式——维护 HTML 默认展示语义的块级标签集合（p/div/li/td/th/h1-h6/section/blockquote 等），集合外元素（含未知/自定义标签）一律按行内保守处理（宁可少删）。
- **文本节点规则**：纯空白节点——邻接块级边界则删除、位于行内内容之间则折叠为单个普通空格；非纯空白节点——只 trim 首尾（块边界侧删净、行内邻接侧保单空格）。节点中部空白序列不压缩（代码/诗歌类有意的内部换行不可猜测，trim 语义只覆盖首尾）。
- **pre/code 豁免**：两棵子树在文本清理与空元素清理中都整体跳过——与 prompt 模板「pre/code 内部只译注释」约束同源。
- **空元素规则**：自底向上（后序）；判空 = 无元素子节点、无清理后非空文本子节点；void 元素（br/hr 等）天然不在候选；表格结构（table/tr/td/th 及表头族）豁免，空 td/th 原样保留。
- **渲染联动**：`sanitizeHtml` 返回空字符串时，定稿分支移除该译文节点（不写空壳）；流式预览路径不动。
- **不动输入侧**：快照/骨架序列化（输入侧）维持「不做空白压缩、保护缩进结构」的既定语义，本 spec 只作用于模型回显。

## Testing Decisions

- 好的测试只断言外部行为：净化函数输入 HTML → 输出 HTML 的字符串形态（无空节点、空白规范化正确、pre/code 原样、表格保留），不断言内部遍历/判定实现。
- 测试接缝：沿用最高既有接缝——`sanitizeHtml` 纯函数 + 离线文档（与 host-discovery.test.js「净化」小节同路径），不需要新接缝。
- 用例清单：① 块间纯空白节点删除；② 行内邻接保单空格不粘连（`Hello <b>bold</b> world`）；③ 句间/词间空格保留；④ 实体空白 `&nbsp;`/`&#10;`/`&#9;`/`&#x200B;` 清理（以实体形式输入断言）；⑤ 空 p/div/span 删除；⑥ 链式空壳 `ul>li` 自底向上清空；⑦ 空 td/th/table 保留；⑧ pre/code 内部（含换行缩进）原样；⑨ 文本节点中部空白不压缩；⑩ void 元素 br 保留；⑪ 既有 banned 标签/危险属性测试回归全绿。
- 渲染联动用例（sanitize 空结果 → 译文节点移除）走既有整页 jsdom 测试基建（先例：content-rescan 系列）。
- Prior art：净化测试先例（host-discovery.test.js 净化小节：script/iframe 移除、on* 属性、javascript: URL）；渲染集成先例（整页沙箱测试）。

## Out of Scope

- 输入侧快照/骨架序列化的空白压缩与结构改动（输入侧保结构是既定语义，另见 ADR-0002 插入式语义）。
- 模型回显的整体包装剥离与首尾 trim（`stripHostWrapper` 既有行为不变）。
- 文本节点中部空白序列的归一/压缩（trim 只覆盖首尾；内部换行压缩涉及语义猜测，不在本轮）。
- 流式预览阶段的空白处理。
- 未知/自定义标签的块级推断（按行内保守处理，不做样式探测）。
- 净化输出为空时的替代文案/占位内容策略（本轮仅移除容器）。

## Further Notes

- 两侧语义分工的延续：输入侧骨架序列化保结构，是给模型完整可翻译上下文；输出侧空白规范与空节点清理，是回显写入前的卫生层。DOM 写入管线只有净化一个闸门，本 spec 让该闸门承担完整卫生职责。
- pre/code 豁免与 prompt 模板既有约束（只译注释、标签原样保留）一致，两侧无需同步改动。
- 空单元格豁免是保守选择：td/th 常作表格排版占位；若未来发现模型回显空表格垃圾更常见，可再讨论收紧。
