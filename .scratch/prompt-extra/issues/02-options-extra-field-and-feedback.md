# 02: 配置页「追加提示词」输入框，及保存反馈只报真正清空的旧值

**What to build:** 「提示词」面板里，模板 textarea 下面多出一个「追加提示词」多行输入框（`rows=4`），它按「空即未设置」工作：填了就落盘、清空就删键、空框不显示灰色示例。面板提示文字说明它的内容插到模板 `{extra}` 的位置、**模板里没写 `{extra}` 时它不生效**（静默，不给保存期提示）。同一票里修掉保存反馈说假话的问题：反馈里的计数从「表单里没值的项数」改为「**存储里原本存在、本次没被写进去**的键」——只改 API 设置、其余从未设置过的用户，保存后得到的就是干净的「已保存 ✓ 下一次翻译生效」。

**Blocked by:** 01（默认值表新增 `extra` 之后本票才有字段可接）

**Status:** resolved

## Comments

- 用户决策（本票相关）：追加提示词**静默不生效**（模板没写 `{extra}` 就不注入，不给提示，只在面板提示文字里说明前提）；反馈口径「**在检测到真正清空旧值时才提示**」；基准取归一化后的存储——存储里的非法值（并发 `-1`、缺 `{host}` 的模板）本来就没生效，清空它不算"删除了设置"，与「空即未设置」同源。
- D8 的代价与收益：每次提交多一次存储读取；换来的是反馈不再对从未设置过的字段说"已删除设置"，且它给出的正是用户想知道的信息——哪些设置真的被删掉了。
- 反向守门的由来：旧口径下"默认值表的键没有输入框"只是让该键永远进不了载荷（安静）；新口径下它一旦被存过，就会**每次保存都被报成"已删除设置"**——正是本票要消灭的假话，所以这条前提必须由断言守住。
