# Spec: 追加提示词 `{extra}`——模板里的自定义插入段，及注入文本不再被二次扫描

## Problem Statement

- 用户想给翻译模型加一条自己的规则（例如"专有名词保留原文"），只能整段改提示词模板：模板很长，改一次要通读全文、还要记得保留 `{host}`，成本高、易错。
- 把规则写进模板等于**冻结模板**：`promptTemplate` 是普通默认值键，一旦保存就永久覆盖后续版本的默认模板（ADR-0003 已记录这一点）。想既加自己的规则、又跟随未来的默认模板，目前没有地方可放。
- `renderPrompt` 目前是**多遍替换**：先替换 `{host}`，再按 vars 逐键替换，每一遍都拿上一遍的产物继续扫描。后果是**被注入的文本会被二次解释**——宿主 HTML 或目标语言里若出现字面 `{target}`，会被悄悄替换成「中文」，prompt 与实际页面内容不符。
- 保存反馈里的"其中 N 项为空，已删除设置"按**表单里没值的项数**计算，与存储无关。新增一个默认空的字段后，从没用过该字段的用户每次保存都会多看到一项"已删除设置"——对从未设置过的字段，什么都没被删除。这是假话，且永远消不掉。
- "凡默认值为空串的字段必须配灰色示例"这条守门把示例变成了新增字段的强制税：示例本应是可选的字段说明，而不是必须编一个的产物。

## Solution

### 1. 新增配置键 `extra`（UI 标签「追加提示词」）

- 默认值 `""`（空字符串），与零痕迹三件套（端点/密钥/模型）同为"默认空"字段。
- 判空规则**自动继承**「空即未设置」：字符串且 trim 后非空才落盘，空值不落盘、读取回退 `""`。内部换行保留（多行可用）。
- 空框时**不显示灰色示例**（按本次决策，示例不再是空默认字段的必配项；见 §4）。

### 2. 默认模板新增 `{extra}` 占位符，独占一行

插入点由用户指定：**「Output exactly one …」与「Example: …」两行之间**。

```
 3 │ Input a HTML fragment of a single page block.
 4 │ Output exactly one translated copy of that fragment.
 5 │ {extra}                                        ← 新增，裸占位符独占一行
 6 │ Example: Input: <html><p>Who are <span>you</span></p></html>
 7 │ Output: <html><p><span>你</span>是谁</p></html>
 8 │ Now translate the following HTML fragment.
 9 │ (空行)
10 │ {host}
```

- `extra` 为空（默认，即未设置）时该行渲染为**一个空行**。模板在 `{host}` 前本来就有一个同类空行，对模型无影响，因此不引入"删空行"这类特殊处理。
- 自定义模板里没写 `{extra}` → 追加提示词**静默不生效**（不提示、不报错、不自动写入占位符）。这条写进配置页提示文字，让用户自己知道前提。
- `{extra}` 与 `{target}` 同类：都在模板里被替换；`{host}` 仍是模板的**必需**占位符（模板缺 `{host}` 照样判空）。

### 3. `renderPrompt` 改为单遍替换（字面保留的机制保证）

现在的实现是 `split/join` 逐键多遍替换，任何一轮注入的文本都会进入下一轮扫描。改为**一次正则扫描模板 + 查表取值**，任何替换结果都不再被扫描：

- 追加提示词里写的 `{target}` / `{host}` / `{extra}` 一律**字面保留**，不展开——不靠"键的排列顺序"这种隐式约定。
- 顺带修掉一个真问题：**注入进模板的宿主 HTML 与目标语言文本也不再被二次扫描**（网页正文里若含字面 `{target}`，此前会被替换成「中文」）。
- 保留既有对外行为：模板缺 `{host}` 抛错；vars 里没有的占位符（如 `{entries}`）原样保留；宿主换行原样保留；`{host}` 注入时包一层 `<html>…</html>`。

### 4. 占位文字规则改造（守门测试随之调整）

占位文字的取值规则改为：

| 字段的默认值 | 占位文字 |
| --- | --- |
| 非空 | **恒为默认值本身**（字符串形式；模板即默认模板全文） |
| 空串，且示例清单里有该键 | 该键的示例（描述性假值） |
| 空串，且示例清单里没有该键 | 空串（空框无灰色提示） |
| 无默认值（未知键） | 空串 |

守门测试的对应调整（**用户指定的方向**）：

- **删除**「凡默认值为空串的字段都必须配占位示例」这条守门（`tests/config.test.js:319`）——正是它把示例变成了强制税。
- **保留**「示例清单里的每个键，其默认值必须是空串」（`tests/config.test.js:333`）——示例只服务于空默认字段，这条防的是死代码与错位。
- **新增**通用断言：默认值非空的字段，占位文字**恒等于默认值本身**（把现有三条零散断言升级为遍历全部字段的循环）。
- `EMPTY_DEFAULT_PLACEHOLDERS` 与其中三个 API 字段的示例**保留不变**（零痕迹：`example.com` / `sk-example-not-a-real-key` / `example-model`，不得出现真实端点、凭证或厂商模型名）；`extra` **不配**示例。

### 5. 保存反馈只报「真正被清空的旧值」

反馈里的计数口径从「表单里没值的项数」改为「**存储里原本存在、本次没写进去的键**」：

```
提交时（写入之前）读取归一化后的存储 → before
cleared = before 中「不在本次载荷里」的键          ← 只有这些才是"被删除的设置"
```

- 常用场景变干净：只改 API 四项、其余从没设置过 → `cleared` 为空 → 提示语就是「已保存 ✓ 下一次翻译生效」，不再多报"已删除设置"。
- 真的清空了旧值（含「恢复默认」+ 保存）→ 逐项可数，文案不变。
- 基准取**归一化后**的存储（现成的 `loadStoredConfig`）：存储里的非法值（并发 `-1`、缺 `{host}` 的模板）本来就没生效，用户清空它**不算**"删除了设置"——与「空即未设置」同源。

### 6. 一处必须条件化的减法（否则出现负数）

现实现里 `const templateItself = 1;` 是写死的 1，后面做 `dropped - 1`。今天不出负数**只是因为**"模板缺 `{host}`"本身意味着模板没写进去，所以那个数至少是 1——**这是靠巧合撑住的推断，代码里没有任何东西保证它**。新口径下 `cleared` 可以为 0：

```
从没存过模板的用户 → 模板框填「只按 {target} 翻译」（非空但缺 {host}）
  专门文案分支成立
  存储里原本没有模板 → 它在 cleared 里根本不该出现 → templateItself 必须是 0
  若照旧减 1 → 提示语出现「另有 -1 项为空，已删除设置、回退默认」
```

因此减法必须条件化：**存储里确实存在该模板时才减 1**。这条要求留"先红后绿"的实测证据。

## User Stories

1. 作为扩展使用者，我想在一个专门的框里写"追加提示词"，这样我加自己的规则时不必通读并重写整个模板。
2. 作为扩展使用者，我想让追加提示词只影响我写的这一段，这样默认模板以后升级时我仍然能跟着升级，而不会因为加了一行规则被永久冻结。
3. 作为扩展使用者，我想在模板里用一个占位符决定追加提示词插在哪里，这样我能控制它出现在示例之前还是之后。
4. 作为扩展使用者，我想在追加提示词里写 `{target}` 时它保持原文，这样"字面写什么就得到什么"，不会因为我不知道的替换顺序被悄悄展开。
5. 作为扩展使用者，我想追加提示词留空时什么都不改变（模板里那一行渲染为空行），这样"不填"和"从没有这个功能"是一样的效果。
6. 作为扩展使用者，我想追加提示词里保留换行，这样我可以写多条规则。
7. 作为扩展使用者，我想清空追加提示词并保存后它回到"未设置"，这样它跟随版本默认而不是被冻结。
8. 作为扩展使用者，我想在我把模板改成自定义模板、忘了写 `{extra}` 时，知道追加提示词不会生效——这条前提写在配置页的提示文字里，我自己看得见。
9. 作为扩展使用者，我想在只改 API 设置、其余从未设置过时，保存反馈不告诉我"删除了设置"，因为它什么也没删——反馈只在我真的清空旧值时才说。
10. 作为扩展使用者，我想在点「恢复默认」清空一整组并保存后，反馈准确告诉我删了几项。
11. 作为扩展使用者，我想追加提示词的输入框不是必填项，留空照样能保存其他设置。
12. 作为扩展使用者，我想新增的追加提示词不要给我一个必须理解的灰色示例（空默认字段没有默认值可显示，就让它空着）。
13. 作为开发者，我想"空"的判定仍然只有一处实现，新字段不需要写任何新判空逻辑，这样新字段不可能有第二套语义。
14. 作为开发者，我想占位文字规则是"非空默认值 → 显示默认值"这样一条，而示例是可选补充，这样新增字段不再被逼着编示例。
15. 作为开发者，我想有一条守门断言保证"默认值表里的每个键都有对应的表单字段（唯一例外：永不可配的 `reasoningEffort`）"，因为反馈计数的正确性依赖它——有键无框的字段一旦被存过就会永远被报成"已删除设置"。
16. 作为开发者，我想 `renderPrompt` 只扫描模板一次，这样"注入的文本被二次解释"这类问题在机制上不可能发生。
17. 作为开发者，我想既有 165 条用例全绿（除按本 spec 明确改写的那些），这样这次改动不偷偷放宽别的断言。
18. 作为扩展使用者，我想在配置页看到追加提示词的用途与前提说明，这样我知道它是干什么的、以及模板里需要写什么。

## Implementation Decisions

**配置模块（`src/config.js`）**

- 默认值表新增 `extra: ""`，紧邻 `promptTemplate` 或作为独立条目（位置不影响语义，注释说明它是"追加提示词"）。不新增任何判空分支——字符串规则自动适用。
- `EMPTY_DEFAULT_PLACEHOLDERS` **保持原样**（三个 API 字段），`extra` 不入表；`placeholderText` 逻辑不变（默认值非空 → 默认值；空串默认值 → 示例；示例缺失 → 空串）。只需同步注释里的规则描述。
- 不新增导出。特别是**不导出** `NON_OVERRIDABLE_KEYS`：反向守门（见下）用"唯一例外 `reasoningEffort`"显式写死，既避免为测试扩接口，也让例外一旦扩大就会转红。

**提示词模块（`src/prompt.js`）**

- `DEFAULT_PROMPT_TEMPLATE` 在「Output exactly one …」与「Example: …」之间插入一行**裸 `{extra}`**。
- `renderPrompt` 改为单遍替换：一次正则扫描模板，命中占位符名就查表取值（`host` 特例：包一层 `<html>…</html>`），查不到则原样保留。替换值不再进入扫描。返回值用函数形式给出，避免 `$&` 之类替换串特殊语法。
- **不新增对外 API**：`renderPrompt(template, hostHtml, vars)` 签名不变，`{extra}` 只是 vars 里多一个键。

**后台代理（`src/background.js`）**

- `renderPrompt(template, hostHtml, { target: cfg.targetLang })` → 增加 `extra: cfg.extra`。既有模板兜底（非空且含 `{host}` 才用存储值，否则回退默认模板）保持不变。

**配置页（`src/options.js`）**

- `GROUPS.prompt.fields` 增加 `"extra"`（放在 `promptTemplate` 之后）。`FIELDS` 由 `GROUPS` 派生，回填、占位注入、保存三条路径自动覆盖新字段，**不需要为新字段写任何分支逻辑**。
- 保存处理改造：
  - 在写入**之前**读取归一化后的存储（`loadStoredConfig`，已有导入）；
  - `cleared` = 存储里有、本次载荷里没有的键；文案统一用它计数；
  - `templateItself` 改为条件常量：仅当"模板被判空"**且**"存储里确实存在模板"时为 1；
  - 局部变量改名：现有的 `const extra`（反馈文案后缀）与新字段同名，必须改成不混淆的名字（如 `extraNote`）。
- 新字段无需专门的保存反馈——它是普通字符串字段。

**配置页标记（`options.html`）**

- 「提示词」面板内、模板 textarea 之后，新增标签「追加提示词」+ `<textarea name="extra" rows="4">`。
- **不新增**「恢复默认」按钮：该组已有的那个按钮按 `GROUPS.prompt.fields` 清空，会自动覆盖新字段。
- 该面板的提示文字补一句：追加提示词的内容插入模板中 `{extra}` 的位置；**模板里没写 `{extra}` 时它不生效**。

**文档**

- `CONTEXT.md` 的「空即未设置」规则里那句"（空串默认值字段的）描述性假示例"按新规则改写：示例是可选字段知识，不再是空默认字段的必配项；占位规则表述为"默认值非空的字段占位即默认值本身"。
- `ADR-0003` 追加一段 `Evolved:`（append-only，不改旧段）：新增 `extra` 键、`{extra}` 成为默认模板的一部分、示例不再强制。
- `AGENTS.md` 的用例数按实测更新。

## Testing Decisions

- 好测试只断言外部行为：纯函数给定输入得到什么输出；配置页给定存储对象后输入框的可见结果（value 与 placeholder）与反馈文案。不断言内部实现细节、不断言调用次数。
- **`renderPrompt` 单遍替换**（`tests/prompt.test.js`）：
  - 默认模板渲染后含注入的追加提示词，且 `{extra}` 无残留；
  - **字面保留**：追加提示词的值里含 `{target}` / `{host}` / `{extra}` 时全部原样出现在结果里；
  - **不再二次扫描**：宿主 HTML 里含字面 `{target}` 时保持原样（这是本次修掉的真问题，必须有用例守住）；
  - 不变行为保持：缺 `{host}` 抛错、未知占位符原样保留、不传 vars 时 `{target}` 原样、宿主换行保留、`<html>` 包装。
- **默认模板插入点**：断言默认模板中 `{extra}` 位于「Output exactly one …」行之后、「Example: …」行之前（按行定位，不写死整篇文本）。
- **占位文字**（`tests/config.test.js`）：
  - 删除「凡空串默认值字段必须配示例」的守门；
  - 新增"非空默认值字段占位恒等于默认值本身"的通用循环断言；
  - 保留「示例清单键 ⇒ 默认值必须为空串」；
  - 保留"占位文字恒为字符串、永不是字面量 `undefined`"。
- **判空/读写同源**（`tests/config.test.js`）：新增 `extra` 的用例行——空串 / 纯空白 / 非字符串为空；trim 后落盘；多行内容保留换行（内部换行不算空白）。`DEFAULTS_SNAPSHOT` 需补 `extra`。
- **配置页**（`tests/options.test.js`）：
  - `PLACEHOLDER` 表补 `extra: ""`（第 117 行的循环遍历全部表单字段，缺这一项会立刻转红）；
  - 回填：存储里有 `extra` → 显示其值；没有 → 空框且无灰色提示；
  - 保存：填入 `extra` → 落盘；清空 → 键从存储里消失（空即未设置）；
  - 追加提示词与自定义模板共存：模板 `"custom rules\n{host}"` + `extra` 非空 → 两者都在载荷里；
  - 「恢复默认」清空「提示词」组 → `promptTemplate` 与 `extra` 两个键都被删；
  - 新增反向守门：`Object.keys(TRANSLATE_CONFIG)` 中除 `reasoningEffort` 外每个键都有同名表单字段（例外的键名显式写死，扩大即转红）。
- **保存反馈（D8）**：
  - 改写依赖旧口径的用例（`tests/options.test.js:192`、`:256` 等）：前提从"表单里有很多空项"换成"**存储里确实存了某项、本次被清空**"；
  - `:235` 那条的期望值改为直写真实数量（不再用 `total - 2` 这类由表单字段数推导的公式——字段数变了公式就失效）；
  - **新增回归用例（本 spec §6 的红→绿证据）**：存储为空 + 模板框填一个非空但缺 `{host}` 的模板 → 走专门文案，且**不含**「另有 N 项为空」，尤其不得出现负数。
- 先例：既有 `tests/helpers/options-sandbox.js`（真实 options.html + 存储替身 + 干净模块实例）与 `tests/helpers/content-sandbox.js` 的"给定输入 → 断言可见结果"写法。
- 每条被改写的断言都要在票的 Comments 里留下：改的是**前提**还是**期望**，以及为什么（不许为了让测试变绿而放宽行为断言）。

## Out of Scope

- 已保存过自定义模板的老用户：模板里没有 `{extra}` 时追加提示词不生效，**不自动补占位符、不迁移、不提示**（提示文字里说明前提即可）。
- 追加提示词的富文本 / 多条规则管理 / 分段开关——只有单个文本框。
- 为 `extra` 配灰色示例占位（按决策不配）。
- 占位符语法本身的改造：转义语法（`{{…}}`）、占位符重命名、模板变量校验（除 `{host}` 必需外不校验其它占位符拼写）。
- 默认模板其余文字的任何调整（本次只在指定位置插入一行）。
- 并发上限、未配置守卫、包装协议、媒体占位/移除等既有行为。

## Further Notes

- 本次改动里**只有一处真行为变化**（除新字段外）：`renderPrompt` 单遍替换——被注入的文本不再被二次解释。它的可观测差异仅出现在"注入文本里含与 vars 键同名的占位符"时，已核实无既有用例依赖旧行为。
- D8 的取舍：反馈在常见场景下**变得更安静**（不再报从未设置过的字段）。代价是每次提交多一次存储读取；收益是文案不再说假话，且它给出了"哪些设置真的被删除"这个用户真正想知道的信息。
- 风险面：`extra` 里若写入含 `{host}` 字面量，它字面保留、不会被替换成宿主——这与"字面保留"一致，但需要在模板里保留 `{host}` 本体（模板缺 `{host}` 仍然判空）。
- 零痕迹：本次不新增任何示例文本，`EMPTY_DEFAULT_PLACEHOLDERS` 里三个假值示例保持原样；文档与测试中不得出现真实端点、密钥或厂商模型名。
