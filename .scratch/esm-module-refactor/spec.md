# Spec: 原生 ESM 换轨——废除双环境导出，统一代码风格

**Status:** ready-for-agent

## Problem Statement

同一份 lib 代码要同时被两套加载机制吃下去：浏览器扩展靠全局符号（content script 的有序脚本表、service worker 的 `importScripts`、配置页的 `<script>` 标签顺序），node 测试靠 CommonJS。于是每个 lib 文件都背着一层双环境导出包装，而且三种写法混用：三个文件是 UMD 工厂取 `globalThis`，一个是 UMD 取 `self`，两个干脆是裸声明 + 手动挂 `globalThis` + 末尾 `module.exports`。

代价是具体的、已经发生过的：

- **依赖关系不在代码里**，只存在于三张互不相干的清单（manifest 的脚本数组、`importScripts` 参数、`options.html` 的标签顺序）。改动顺序不会有任何静态报错，只会在运行时炸掉——曾经真的炸过一次（UMD 全局分支挂载错位，HostDiscovery 未定义），事后只能补一个专门测「全局符号契约」的测试来看门。
- **测试基建为绕过全局体系而膨胀**：内容脚本集成测试要靠一个手搓 `vm` 沙箱，按 manifest 顺序把文件逐个塞进上下文，才能让读全局的 IIFE 跑起来。
- **生产代码里有「我在测试里吗」的判断**：配置模块两处 `typeof chrome === "undefined"` 分支、净化模块的 `typeof document !== "undefined"` 兜底，都是为 node 测试而存在的环境探测。
- **风格分两个年代**：宿主发现与净化两个模块通篇 `var` + 手写索引 for 循环遍历 NodeList，其余文件是 `const`/箭头/`for...of`。仓库无 lint、无 formatter，没有任何东西阻止这种漂移继续。
- **注释腐坏**：文件顶部十几行中文横幅里，相当一部分是历史沿革（「语义来源：v3 内联实现原样迁移」「兑现 ADR-0003 预留接缝」），描述的是代码走过的路而不是代码现在的样子——这类注释只会随时间变成谎言。

## Solution

**换成原生 ESM，零构建步骤。** 依赖关系从三张清单搬进代码本身的 `import` 语句：

- **service worker** 声明为 `"type": "module"`，用静态 `import` 取代 `importScripts`。
- **配置页**用 `<script type="module">`，标签顺序不再有语义。
- **content script** 在 manifest 里退化成一个 classic **加载器**：它同步注册消息监听器并缓冲请求，再动态 import 真正的会话模块，import 完成后把缓冲的请求转发进去。同步注册消除了「扩展刚注入完、用户已经右键」的竞态——否则那一次点击会被 background 当成受限页而**静默无反应**。
- 模块文件列入 `web_accessible_resources` 并开启 `use_dynamic_url`：动态 import 要求资源可被页面访问，而轮换 URL 堵住随之而来的唯一实际损失——页面用固定 URL 探测扩展是否安装（指纹识别）。模块里没有凭证，密钥只在同步存储；页面 import 到的模块拿不到扩展 API，是惰性的。

**双环境包装、`globalThis` 赋值、`importScripts`、manifest 有序脚本表、全局符号契约测试，全部消失。**

顺势兑现三件本来被全局体系挡住的事：

- **环境探测下沉为依赖注入**：内容脚本导出一个接受 `document`/`chrome`/`getComputedStyle` 的会话工厂——追上宿主发现模块**已经在用**的那个更好形态。生产代码里不再有环境嗅探，测试直接 import 模块并注入 jsdom，`vm` 沙箱组装整个删除。
- **配置模块重塑**：两条读取语义（运行时空值回退默认 / UI 回填保存什么读什么）的两份近乎重复的实现合一；提示词模板降级为普通默认键，它带来的隐式跨模块耦合与那句加载顺序注释一并消失。
- **风格基线固化**：ESLint + Prettier 落地，`var`/索引循环现代化，注释瘦身为单行——历史沿革删除，ADR 引用只留一行指针。

**行为不变**：98 个既有测试的断言一字不改（只改加载方式）。

## User Stories

1. 作为改这个仓库的人，我希望模块依赖写在 `import` 语句里，这样漏依赖或搞错顺序在读代码时就能看出来，而不是等运行时炸。
2. 作为改这个仓库的人，我希望新增一个 lib 文件时只需要写 `import`，不需要同时改 manifest 脚本数组、`importScripts` 参数、`options.html` 标签顺序和全局符号契约表四个地方。
3. 作为改这个仓库的人，我希望删掉一个 lib 文件时不会留下三张清单里的幽灵引用。
4. 作为改这个仓库的人，我希望每个模块只有一种导出写法，这样读第二个文件时不用重新辨认它属于哪一代。
5. 作为改这个仓库的人，我希望生产代码里不出现「当前是不是测试环境」的判断，这样读到的每一行都是真实运行的那一行。
6. 作为改这个仓库的人，我希望测试直接 import 被测模块，这样跳转定义、堆栈行号、断点都能正常工作——而不是穿过一层 `vm` 上下文。
7. 作为改这个仓库的人，我希望内容脚本集成测试的沙箱基建只保留时序控制与替身（手动时钟、mock 端口、消息总线），不再承担「按清单顺序装配全局」的职责。
8. 作为改这个仓库的人，我希望配置的两条读取语义共用一份实现，这样改判空规则时不会只改一半。
9. 作为改这个仓库的人，我希望提示词模板的默认值和其它配置项一样是默认值表里的普通一项，而不是靠另一个模块挂全局供配置模块消费。
10. 作为改这个仓库的人，我希望内容脚本按职责分成若干模块（会话状态、DOM 写入与动画、端口流程、观察器调度），这样改动画不必读端口协议。
11. 作为改这个仓库的人，我希望 `var` 与索引 for 循环不会再出现，并且有工具替我拦住它复发。
12. 作为改这个仓库的人，我希望注释只解释「为什么这么写」，历史沿革交给 git 与 ADR，这样注释不会随时间变成谎言。
13. 作为改这个仓库的人，我希望一条命令同时跑 lint 与测试，这样风格问题不需要靠 review 逐行盯。
14. 作为改这个仓库的人，我希望排版由 formatter 决定，这样 diff 里不再混入与改动无关的换行噪音。
15. 作为扩展使用者，我希望重构之后翻译、还原、动态补翻、错误提示、并发上限的行为与之前完全一致——包括未配置时那条「打开配置页」的指引。
16. 作为扩展使用者，我希望扩展刚注入完就右键「翻译页面」也能生效，而不是静默无反应、需要再点一次。
17. 作为扩展使用者，我不希望任意网页能用一个固定 URL 探测出我装了这个扩展。
18. 作为扩展使用者，我希望重构不引入构建步骤——`chrome://extensions` 里加载的目录仍然就是仓库目录，改完刷新即可。
19. 作为后来读 ADR 的人，我希望能查到为什么选原生 ESM 而不是打包器，以及 `use_dynamic_url` 换掉了什么风险。
20. 作为后来读 ADR 的人,我希望描述 `importScripts` 的那份旧 ADR 明确标注它已被静态 import 取代，而不是留着一段与代码矛盾的文字。
21. 作为改这个仓库的人，我希望有个测试盯住「manifest 与配置页引用的文件都存在、动态 import 的模块图都登记进了可访问资源」——这是换轨之后新出现的一类错误。

## Implementation Decisions

### 模块体系

- 全部源码为 ESM。`package.json` 加 `"type": "module"`，测试与配置文件同为 ESM。
- service worker：manifest 的 background 声明加 `"type": "module"`；`importScripts` 换成静态 `import`。
- 配置页：`<script type="module">` 单入口，其余依赖由 import 图解决。
- content script：manifest 里注册的是一个 **classic 加载器**（不是 `type: module`——MV3 的 content script 声明不支持模块）。加载器职责有且仅有两件：同步注册消息监听器把请求缓冲进队列（回应通道保持打开）；动态 import 会话模块，就绪后把缓冲请求依次转发。加载器不含业务逻辑。
- `web_accessible_resources` 覆盖源码目录，`use_dynamic_url: true`。
- **不引入打包器**，不产生 dist；`chrome://extensions` 加载的目录就是仓库目录。

### 目录

- 全部源文件收进 `src/`（原 `lib/` 并入），根目录只留 manifest、配置页 HTML 与工具配置文件。理由：`web_accessible_resources` 需要一个能一句话覆盖的路径前缀。
- 不按角色再分子目录（content/background/shared）——对这个体量的仓库是过度分类。

### 依赖注入

- 内容脚本导出会话工厂，接受 `document`、`chrome`、`getComputedStyle` 三个环境依赖；真实全局由加载器接入。形态对齐已有的宿主发现工厂。
- 配置读取接受注入的 storage；净化函数已有的显式 `doc` 参数保留，去掉它的全局兜底分支。
- 生产代码中不再出现 `typeof chrome`/`typeof module`/`typeof document`/`typeof globalThis` 形式的环境探测。

### 配置模块重塑（行为不变）

- 两条读取语义合成一份核心实现 + 两个薄入口：运行时语义（`null`/`undefined`/`""` 回退默认）与 UI 回填语义（空值透传空串）的差异收敛成一个参数。
- 提示词模板成为默认值表里的普通字符串键。它一旦入表，两个 merge 函数里的模板特判块可直接删除——通用字符串分支产出的结果与今天逐字一致（运行时空值回退默认模板、UI 空串透传）。连带消失：模板模块的三行全局赋值、service worker 里那句「模板模块须先于配置模块加载」的顺序注释。
- 消费侧「模板不含 `{host}` 时回退默认」的兜底保留不动。

### 内容脚本拆分（行为不变）

- 按职责拆为四块：会话状态与生命周期（会话标志、代号作废、在途端口登记、还原）、DOM 写入与加载动画（译文节点建立/样式/流式预览/定稿/错误标记）、单宿主端口流程与并发池、观察器与防抖调度。
- 拆分**不新增测试接缝**：四块都透过既有的消息/端口→DOM 接缝观测（见 Testing Decisions）。

### 风格

- ESLint 9 flat config：`recommended` 基线 + `no-var`、`prefer-const`、`eqeqeq`、`no-implicit-globals` 四条。`recommended` 不管 `var` 与 `prefer-const`，而两代写法混用正是本次要根治的东西——不加这两条，lint 装了也拦不住复发。
- globals 按目录三段：源码目录为 browser + webextensions，测试目录为 node，根配置文件为 node。
- Prettier 用默认值，仅 `printWidth: 100`（现有代码普遍宽于 80，设 80 会产生大量与本次无关的换行噪音）。
- 脚本拆为 `lint` 与 `test:unit`，`test` 串联二者。
- 两个 `var` 时代的模块现代化：`var` → `const`/`let`，手写索引 for 循环 → `for...of`（`querySelectorAll` 结果可迭代；就地删除元素的循环需先物化成数组，避免遍历中改动集合）。
- 注释瘦身为单行：删除历史沿革（「v3 迁移而来」「兑现 ADR-000x 接缝」「语义来源」「行为零变化」），保留解释非显然选择的说明（如媒体占位保住语序），ADR 引用压成一行指针。

### 文档

- 新增 ADR「原生 ESM 模块」：记录换轨、被否的打包器方案与「原样保留全局只删包装」方案、`use_dynamic_url` 的指纹权衡、以及 content script 加载器的竞态处理。
- 在 `importScripts` 那份 ADR 末尾**追加**演进段落说明它已被静态 import 取代（沿用该目录已有的「追加演进段落而非改写原文」先例，不改原文）。
- README 与 AGENTS.md 校准到新的目录与命令。
- **`CONTEXT.md` 不动**：它是领域术语表，模块体系不是领域词汇。

## Testing Decisions

好测试只断言外部行为。本次重构的性质决定了一条硬约束：**既有断言一字不改**，只改被测模块的加载方式；断言若需要改动，说明这不再是重构，必须先回头讲清楚。

沿用四条既有接缝，只新增一条：

- **S1 纯函数模块**（既有）：文本判定、净化、提示词渲染、配置合并——直接 import 后断言返回值。`require` → `import`，断言不动。
- **S2 内容脚本：消息与端口进 → DOM 出**（既有，观测面不变）：透过消息总线发翻译/还原指令，用 mock 端口喂 delta/done/error，断言译文节点的 DOM 与在途端口峰值。**变的只有装配**：`vm` 按清单顺序塞文件 → 直接 import 会话工厂并注入 jsdom。手动时钟、mock 端口、消息总线原样保留。这条接缝同时是内容脚本拆分的**唯一**接缝——四个新模块不各自加测试，否则拆分会长出四个新接缝，把内部结构焊死在测试里。
- **S3 宿主发现工厂注入 jsdom**（既有，不动）：仓库里已经是最好的形态，本次只删它的 UMD 包装。
- **S4 配置读取的返回值**（既有，不动）：storage 变成注入之后，测试从「没有扩展全局所以走 fallback 分支」变成「传一个假 storage」，断言的仍是同一个返回值。
- **S5 manifest 清单一致性**（新增，取代全局符号契约测试）：静态检查 manifest 与配置页引用的文件都存在，且 content script 动态 import 的模块图全部被 `web_accessible_resources` 覆盖。它守的是换轨之后**新出现**的错误类别（漏登记 → 运行时 import 失败），不碰任何运行时行为。

原有的「全局符号契约 / 加载顺序」测试**随全局体系一并删除**：ESM 之后不存在全局符号，它守的错误类别已经不可能发生。

明确不加的接缝：不给加载器单独写测试（它只有转发逻辑，且真实行为依赖扩展 URL 解析，jsdom 下测的是替身而非真相——它的正确性由下面的手工验收覆盖）；不给 lint/format 写测试（`npm run lint` 自己就是那个检查）。

### 必须手工验收的项（无法在开发机自动验证）

开发机没有 Chrome，以下三项只能装载扩展手工确认，**不得当作已验证**：

1. content script 里动态 import 扩展资源在真实 Chrome 中确实可用——**这是整个方案风险最高的一点**。
2. `use_dynamic_url: true` 与上一条并存不冲突。
3. 模块 service worker 与 `use_dynamic_url` 的 Chrome 版本下限，据此写入 manifest 的最低版本声明（现在没有这一项）。

预设的降级阶梯（按序尝试，每一级都要如实记录进 ADR）：若第 2 项冲突 → 关掉 `use_dynamic_url`，接受指纹识别；若第 1 项根本不可用 → 该方案的前提失效，**停下来回到决策**，候选是「仅为内容脚本引入最小打包器」，这超出本 spec 范围。

## Out of Scope

- 引入打包器、TypeScript、类型检查。
- 翻译行为、提示词内容、宿主发现规则、净化白名单、并发默认值的任何改动。
- `CONTEXT.md` 的术语增删。
- 历史 ADR 原文改写（只允许追加演进段落）。
- 从 git 历史中清除曾经提交过的凭证（ADR-0003 已记为 owner 的独立任务）。
- Firefox / 其它浏览器兼容。
- CI 配置。

## Further Notes

### 2026-08-29 修订：`use_dynamic_url` 经真机实测证伪，已降级为不启用

本 spec 的 Solution 与 Implementation Decisions 写于决策阶段，其中「模块文件列入 `web_accessible_resources` 并开启 `use_dynamic_url`」及 User Story 17（防固定 URL 探测）在实施前的真机验证（工单 01，Edge 148 headless）中被证伪：开启轮换后内容脚本动态 import 报 `Failed to fetch dynamically imported module`，且隔离实验（同一 URL 下 `fetch` 返回 200 而 `import` 失败）证明是模块加载器被轮换 URL 掐断，非登记或路径错误。经用户拍板采用降级方案 A：不启用 `use_dynamic_url`，User Story 17 相应放弃。方案与证据详见 docs/adr/0006-native-esm-modules.md。原文叙述保留不改，以此修订段为准。

- 与 `.scratch/` 下既有 feature 正交：那些管翻译语义，本 spec 只管模块体系、代码风格与测试装配。
- 换轨工单是**原子**的：lib 一旦成为 ESM，三个消费端必须同时改，无法按文件切片提交中间态。风格基线工单可以先行，配置重塑与内容脚本拆分必须在换轨之后，两者互相独立。
