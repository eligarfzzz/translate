# Spec: 短文本缓存查看与命中次数（cache-inspection）——设置页分页表格

## Problem Statement

- 短文本缓存已经能跨页面保存并回放译文，但用户无法从设置页确认库中实际保存了哪些原文和译文，只能借助浏览器开发者工具查看 IndexedDB。
- 缓存默认最多保存一万条，直接一次性展示既不可用，也会给设置页带来不必要的渲染负担。
- 当前命中只会刷新最后使用时间，用户无法判断某条缓存是否真正发挥过作用、被复用了多少次。

## Solution

在设置页「通用」TAB 增加短文本缓存内容表格，展示全部缓存条目的骨架原文、原始回显、每条累计命中次数和最后使用时间。表格按最后使用时间倒序，每页固定二十条，提供上一页、下一页、页码与总条数。进入「通用」TAB 时读取第一页，清空缓存后回到第一页并显示最新结果。

每条缓存新增累计命中次数：新条目从零开始，每次真实命中并回放前加一；功能上线前已存在的条目从零开始，不追溯历史命中。查看和统计均不受缓存开关影响，也不改变翻译、会话重用、自动清理和手动清空的既有行为。

## User Stories

1. 作为用户，我希望在设置页直接看到缓存内容，这样不必打开开发者工具。
2. 作为用户，我希望同时看到原文和译文，这样可以核对缓存里保存的对应关系。
3. 作为用户，我希望表格分页显示，这样缓存很多时设置页仍然可用。
4. 作为用户，我希望最近使用的条目排在前面，这样能优先看到当前仍在发挥作用的缓存。
5. 作为用户，我希望看到当前页、总页数和总条数，这样可以了解缓存规模并继续翻页。
6. 作为用户，我希望空缓存有明确的空状态，而不是一张让人误以为加载失败的空白表。
7. 作为修改过翻译配置的用户，我希望仍能查看旧配置指纹留下的条目，这样可以了解实际占用存储的全部内容。
8. 作为关闭了短文本缓存的用户，我希望仍能查看残留条目，这样可以在决定是否清空前先检查内容。
9. 作为用户，我希望看到每条缓存的累计命中次数，这样可以判断它被复用了多少次。
10. 作为用户，我希望新缓存初始命中次数为零，这样「写入」和「命中回放」不会被混为一谈。
11. 作为老版本用户，我希望已有条目也能显示命中次数，即使升级前的历史次数无法恢复。
12. 作为用户，我希望只有实际命中才增加次数，未命中和普通上游翻译不会虚增统计。
13. 作为用户，我希望同一条缓存被新的上游结果覆盖时保留已有命中次数，这样并发重复请求不会把统计意外清零。
14. 作为用户，我希望缓存被清空、过期或淘汰后，若同键重新建立则重新计数，因为被删除的旧统计不应转移到新条目。
15. 作为用户，我希望看到最后使用时间，这样可以结合命中次数判断条目的活跃程度。
16. 作为用户，我希望缓存里的 HTML 以文本展示，这样缓存内容不会在设置页执行或改变页面结构。
17. 作为用户，我希望主动读取缓存失败时看到失败提示，而不是把故障误报成「暂无缓存」。
18. 作为用户，我希望点击「清空缓存」后表格立即反映结果，不需要重开设置页。
19. 作为用户，我希望查看缓存不需要点击「保存」，也不会改写任何设置。
20. 作为维护者，我希望设置页仍通过 background 读取缓存，这样数据库结构知识不会复制到设置页。
21. 作为维护者，我希望新功能复用现有缓存键和最后使用时间索引，避免重复保存原文或增加不必要的数据库迁移。
22. 作为维护者，我希望缓存查看与命中统计不改变内容脚本的端口协议和译文渲染路径，从而把回归范围限制在缓存与设置页。

## Implementation Decisions

- **D1 设置页位置**：缓存内容表格位于「通用」TAB，与现有缓存设置和「清空缓存」动作放在一起。表格不是表单字段，不参与保存。
- **D2 查看范围**：表格展示整个缓存库，不按当前配置指纹过滤；读取不加载配置，也不受 `cacheEnabled` 影响。理由与整库手动清空一致：旧指纹条目虽然不再命中，却仍实际占用存储。
- **D3 展示内容**：最终列为骨架原文、原始回显、命中次数、最后使用时间。原文从缓存主键还原，译文使用缓存中保存的原始回显；两者都以纯文本放入表格，不解析为 HTML。
- **D4 分页与顺序**：每页固定二十条，按最后使用时间倒序。界面提供上一页、下一页、当前页、总页数和总条数；空库显示明确空状态并禁用翻页。
- **D5 页码边界**：请求页码超出当前范围时返回有效页码及该页内容；空库归一到第一页的空结果。自动清理或其他页面写入造成条数变化时，以当次查询结果为准。
- **D6 加载与刷新**：每次进入「通用」TAB 读取第一页；翻页读取对应页；手动清空成功后回到第一页重新读取。离开再进入该 TAB 同样重新读取，不提供持续自动刷新。
- **D7 存储查询**：缓存存储模块新增分页读取能力，复用现有最后使用时间索引进行倒序游标查询，并通过游标主键取得骨架原文。值中不重复保存原文；总条数由存储统计返回。
- **D8 消息契约**：新增独立的缓存列表请求—响应消息，请求携带页码和每页条数，成功响应携带成败、实际页码、每页条数、总条数及条目列表；每个条目包含原文、原始回显、命中次数和最后使用时间。该消息与手动清空、自动清理保持各自契约，不合并成带模式参数的消息。
- **D9 主动读取失败**：设置页主动查看缓存时，IndexedDB 故障要记录日志并返回失败态；设置页显示读取失败提示，不能伪装成空缓存。翻译流程中的缓存故障仍然静默降级，既有边界不变。
- **D10 命中次数口径**：命中次数是按缓存键累计的真实回放次数。新键写入时为零；读取到记录时，在返回缓存回显前将次数加一，并在同一读写事务中刷新最后使用时间。未命中不增加次数。
- **D11 旧数据与覆盖写**：缺少命中次数字段的旧记录按零处理。写入一个已存在的键时保留其现有次数，只更新回显和最后使用时间；新键才从零开始，避免同轮重复请求或覆盖写将已有统计清零。
- **D12 数据库演进**：命中次数是普通值字段，列表继续使用现有索引，不新增对象仓库或索引，因此不提升数据库版本，也不做全库迁移。旧条目在读取或后续命中时自然采用新字段。
- **D13 删除后的统计**：手动清空、过期删除和容量淘汰都删除整个条目；同键以后重新写入时作为新条目从零计数。不另行保存已删除条目的历史统计。
- **D14 统计边界**：本功能只提供每条缓存的累计命中次数，不记录未命中次数，不计算全局命中率，也不增加独立的统计面板。
- **D15 既有行为不变**：缓存写入条件、命中回放、会话重用跳过缓存段、自动清理、手动清空、内容脚本端口协议和译文渲染均保持原语义。查看缓存不写入 `chrome.storage`，不需要保存设置。
- **D16 安全与零痕迹**：原文和原始回显仅作为文本展示，不注入可执行 HTML；代码、测试和文档继续使用假端点、假密钥和假模型名，不引入真实配置或用户缓存数据。

## Testing Decisions

- 好测试只断言外部可观察行为：存储返回的分页与条目内容、runtime 消息载荷、设置页 DOM、发出的后续消息、翻译命中前后的统计结果；不断言私有变量或内部调用次数。
- **缓存存储**：沿用存储工厂注入内存 IndexedDB 的既有接缝。覆盖倒序、固定页大小、边界页、空库、整库条目、读取失败、旧记录缺字段、命中递增、覆盖写保留次数和删除后重建归零。内存替身只补充本功能实际使用的游标方向与分页能力。
- **background 集成**：沿用 chrome、fetch、端口和 IndexedDB 沙箱，验证缓存列表消息的完整请求—响应契约、开关关闭仍可读取、故障可见，以及实际缓存命中后再次查询能看到次数增加；既有清空与清理消息契约保持回归。
- **设置页**：沿用解析真实设置页 HTML 的 jsdom 沙箱，验证进入 TAB 加载、翻页消息、总条数与页码、空状态、失败提示、清空后刷新、全部列的文本渲染和 HTML 不执行。新增动作元素不得进入配置字段集合。
- **回归验证**：每个实现工单都运行完整测试与 lint；内容脚本侧无需新增测试接缝，但既有缓存命中回放和会话重用用例必须保持绿色。
- **关键变异验证**：把命中递增移除、把覆盖写改成次数归零、把列表改成只读当前指纹或受开关控制时，对应测试必须转红。

## Out of Scope

- 全局命中率、未命中次数、节省请求数等汇总统计，以及独立统计面板。
- 搜索、按指纹过滤、自定义排序、可调每页条数。
- 单条编辑、单条删除、选择性清空。
- 缓存导入导出、跨设备同步。
- 表格持续自动刷新、跨标签页实时同步。
- 为翻页建立跨请求的稳定快照；并发写入或清理后的当次查询差异予以接受。
- 恢复功能上线前已经发生的历史命中次数。
- 长文本缓存、在途相同原文合并，以及现有缓存淘汰策略的调整。

## Further Notes

- 本需求把旧短文本缓存 spec 中的统计面板边界收窄为：每条缓存的命中次数进入范围，全局命中率仍不在范围内；同时把旧手动清空 spec 中的缓存条目浏览搬进范围。
- 决策同步进根上下文词表与 ADR-0008 的演进段，不新增 ADR：本功能是既有短文本缓存决策的自然扩展。
- 查看范围与手动清空范围一致，均为整库；当前配置指纹只决定翻译时哪个键可以命中，不决定用户能查看哪些实际数据。
- 命中次数从本功能生效后开始累计，旧条目显示的零不代表历史上从未命中。
