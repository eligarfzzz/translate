# Spec: 空即未设置——空值不落盘、读取回退默认、占位符显示默认

## Problem Statement

配置项为空时，扩展的实际行为、配置页显示的内容、用户心中以为的结果，三者对不上：

- 用户清空「并发上限」保存后重开配置页，看到的是 20 而不是空——UI 走"保存什么读什么"，而运行时空值回退默认，数字字段的"空"在数字侧直接丢失（清空后重开显示 20，再点保存又把 20 写回存储）。
- 用户清空「目标语言」后配置页显示空，实际翻译却用「中文」；UI 与生效值不一致，用户无法从界面判断真实行为。
- 粘贴或误输入留下的是纯空白（`"   "`）时，它既不算空也不算有效值：绕过"未配置"守卫，把请求发到 `chrome-extension://<id>/chat/completions`，用户看到的是莫名其妙的网络错误，而不是"请先配置"的指引。
- 提示词模板非空但不含 `{host}` 时，运行时整段静默丢弃换成默认模板，用户写的自定义规则完全没生效，只有保存那一刻的一行提示。
- 「恢复默认」按钮把默认值的**字面量**写进存储，等于把用户永久冻结在那一版默认上，之后的版本更新再也到不了他——而"回到默认"本该是删掉这个设置。

## Solution

统一为一条语义：**空 = 未设置（empty means unset）**。

- **写路径**：配置页保存时，判定为空的字段不写入存储；整包重写存储里的 `config`，只含非空键——等价于删除所有空键。全部为空时删除 `config` 键本身。
- **读路径**：先取默认配置全量，再把存储中判空后的非空值覆盖上去，得到实际生效配置。不存在第二条读取语义。
- **配置页**：存储里没有该键时输入框为空，并以灰色 placeholder 显示该项默认值（提示词模板显示完整默认模板文本）；有非空值时显示真实保存值（保存前统一 trim）。
- **「恢复默认」**：把该组输入框清空，由 placeholder 显示将生效的默认值；点保存才落盘（落盘即删键），从此该组配置永远跟随版本默认。

判空规则（按默认值的类型）：

| 默认值类型 | 有效（保留并归一化） | 空 / 无效（删除、回退默认） |
| --- | --- | --- |
| 字符串 | 字符串且 `trim()` 后非空 → 存 trim 后的值 | null / undefined / 非字符串（数字、对象、数组）/ trim 后为空 |
| 数字 | number 或数字串，有限、大于 0 **且为整数** → 存为 number | null / undefined / 空串 / NaN / 非数字串 / 0 / 负数 / 非有限 / 小数 |
| 提示词模板（字符串 + 语义校验） | trim 非空**且包含 `{host}`** → 存 trim 后的值 | 上表字符串的全部空值，外加"trim 非空但不含 `{host}`" |

## User Stories

1. 作为扩展使用者，我想在配置页清空一个输入框再保存后，重开配置页看到的仍然是空，这样我知道这个设置已经交还给默认。
2. 作为扩展使用者，我想在输入框为空时看到灰色的默认值占位文字，这样我知道留空会得到什么，不必去翻源码。
3. 作为扩展使用者，我想在 placeholder 里直接看到提示词默认模板的全文，这样我能照着改而不是从零写。
4. 作为扩展使用者，我想点「恢复默认」后输入框变成空并显示默认值占位，这样我得到的是"跟随版本默认"，而不是把当前默认冻结进存储。
5. 作为扩展使用者，我想「恢复默认」的提示文案明确说明"已清空，将使用默认值，点保存生效"，这样我知道它做了什么、以及还需要一步保存。
6. 作为扩展使用者，我想在 API 端点里只输入空白字符时被当作未配置，这样我得到的是"未配置 API 端点，请打开配置页"的指引，而不是发到扩展自身地址的莫名错误。
7. 作为扩展使用者，我想在 API 密钥里只输入空格时被当作未配置，这样不会把 `Bearer ` 空格发到上游。
8. 作为扩展使用者，我想在模型名只输入空格时被当作未配置，这样我不会收到上游"模型不存在"的报错。
9. 作为扩展使用者，我想清空目标语言后运行时自动用「中文」，这样提示词里永远不会出现空语种。
10. 作为扩展使用者，我想清空并发上限后运行时自动用 20，且重开配置页看到的是空框 + 灰色 20，这样 UI 与生效值一致。
11. 作为扩展使用者，我想填 0、负数或小数作为并发上限时被当作无效并回退默认，这样不会出现小数被静默取整成 1 这种怪现象。
12. 作为扩展使用者，我想在 URL 前后不小心带入空格时被自动去掉再保存，这样我不会拼出带空格的坏 URL。
13. 作为扩展使用者，我想在提示词模板漏掉 `{host}` 时于保存那一刻得到明确反馈、且该模板不被持久化（等同留空、回退内置默认），这样我不会误以为自定义规则生效了。
14. 作为扩展使用者，我想配置页的显示与运行时的生效值在任何存储形态下都一致，这样界面不会对我撒谎。
15. 作为扩展使用者，我想旧的、已删除的配置键（如 batchSize）在我下次保存时被自然清掉，这样存储里不会长期积累垃圾。
16. 作为扩展使用者，我想存储里只剩空值时 `config` 键被彻底删除（而不是留下一个空对象），这样同步存储保持干净。
17. 作为扩展使用者，我想 `reasoningEffort` 永远不可配置、存储里的任何取值都被忽略，这样"关闭思考"不会被意外打开。
18. 作为扩展使用者，我想在保存后看到明确的反馈（包括"某几项为空、已回退默认"），这样我知道这次保存到底写了什么。
19. 作为扩展使用者，我想一个字段留空不影响其他字段的回填，这样部分配置与默认值可以自由混用。
20. 作为扩展使用者，我想在未配置 API 三项时，右键翻译仍给出"打开配置页"的指引，这样清空空值与从未配置得到同样的可操作结果。
21. 作为开发者，我想"空"的判定只有一处实现，写路径与读路径共用它，这样两条路径的判空规则不会漂移。
22. 作为开发者，我想配置合并与剪枝都是纯函数、由 node:test 覆盖，这样回归不需要浏览器。
23. 作为开发者，我想删掉 UI 专用的 raw/runtime 两条语义，只留一条，这样读代码的人不必记得"当前在哪条语义上"。
24. 作为开发者，我想配置页在 jsdom 下可测（给定存储 → 输入框 value 与 placeholder），这样"显示默认值"这类 UI 行为有自动化保护。
25. 作为开发者，我想 ADR-0003 追加一段演进记录、CONTEXT.md 增加一条规则，说明"空即未设置、恢复默认 = 清空 + 保存 = 删键"，这样后来者不会重蹈冻结默认的坑。
26. 作为扩展使用者，我想 placeholder 对默认值为空串的三个 API 字段给出描述性示例（端点/密钥/模型），这样没有默认值可显示时我仍知道该填什么形状。

## Implementation Decisions

- **单一判空收口（唯一 seam）**：配置模块内新增一个纯归一化函数，输入"默认值 + 存储/表单原始值"，输出"归一化后的值或空"。写路径与读路径都必须经由它，任何一方不得自行实现判空。判空规则严格按上文表格，不区分"运行时空值"与"UI 空值"。
- **配置模块对外的纯函数接口**（名称即契约）：
  - `sanitizeStored(defaults, raw)`：唯一的归一化入口，返回只含有效键、值已归一化的新对象；`raw` 非对象/数组/字符串一律视为空对象。
  - `mergeConfig(defaults, raw)`：读路径，等于"默认全量 + `sanitizeStored` 的结果"。
  - `pruneConfig(defaults, formValues)`：写路径，配置页用它从表单值构造存储载荷（HTML 输入恒为字符串，故数字字段必须走归一化转 number、字符串字段必须 trim）。
  - `readStored(storage)`：读 sync 存储里的 `config` 原始对象，缺失返回 null。
- **异步加载器收敛为一条语义**：删除 `loadConfigRaw` / `mergeConfigRaw`；保留 `loadConfig`（读路径，供 background 与 content 使用），新增 `loadStoredConfig`（返回已归一化的"存储中真实存在的配置"，供配置页回填——配置页需要的正是"哪些键被真正设置过"，而不是合并了默认值的全量对象）。
- **配置页回填**：每个字段的 placeholder 恒为该项默认值的字符串形式（提示词模板即默认模板全文），来源是默认值表本身、运行时注入，不手写进 HTML；输入框显示的是存储中真实存在的非空值（placeholder 在输入框有值时本就不显示）。
- **placeholder 的空默认值处理**：默认值就是空串的三个 API 字段（端点/密钥/模型）没有可显示的默认值，使用描述性示例，且示例必须是明显的假值以延续零痕迹默认（沿用测试与文档里既有的 `example.com` / `sk-example…` / `example-model` 一类写法，不得出现任何真实凭证或厂商模型名）；它们"回退默认"的结果仍是空，由未配置守卫给出可操作指引。
- **保存**：`pruneConfig` 结果为空对象时调用 `storage.sync.remove("config")`，否则 `storage.sync.set({ config: payload })`。整包重写天然清理旧键，不需要新增迁移逻辑。
- **保存反馈**：非空项照常提示"已保存 ✓ 下一次翻译生效"；如果存在被判空而删除的项，追加上"其中 N 项为空，已删除设置、回退默认"；模板因缺 `{host}` 被判空时给出专门文案（区别于"模板为空"）。
- **「恢复默认」按钮语义变更**：单击只清空该组输入框（placeholder 随之显示默认值），不写存储；文案改为"已清空「X」，将使用默认值，点保存生效"。分组表仍是 TAB 归属、恢复默认作用域、字段清单的唯一事实来源。
- **提示词 `{host}` 校验进入归一化层**：保存时的判空与运行时读取时的回退因此同源，配置页的提示与 background 的行为不会再分叉。
- **background 的模板兜底保留**：作为纵深防御（防任何绕过归一化的值让渲染抛错），但不再承担主语义。未配置守卫（端点/密钥/模型任一为空 → 经 error 通道回告并附配置页指引、不发起网络请求）保持不变。
- **数字字段**：并发上限必须是正整数，归一化后以 number 写入存储（配置页读到的也是 number，回填进 number 输入框）。
- **文档**：ADR-0003 追加第三段演进记录（"恢复默认 = 清空 + 保存 = 删键"成为一等公民，raw/runtime 双语义收敛为一条）；CONTEXT.md 的 Rules 增加一条"空即未设置"；配置页提示词面板的 hint 改写为"留空使用内置默认模板；填写内容必须包含 `{host}`，否则保存时视为留空"。
- 配置页其余部分（TAB 切换、日志导出/清空、status 提示节奏）不动。

## Testing Decisions

- 好测试只断言外部行为：纯函数给定输入得到什么输出，以及配置页给定存储对象后输入框的可见结果（value 与 placeholder）。不断言内部实现细节、不断言调用次数。
- **单一用例表驱动两条路径**：同一批"默认值 + 原始值"用例分别喂给读路径与写路径，断言两者对"空"的判断完全一致——这是"判空不漂移"的自动化保障，也是本 spec 的核心测试形态。
- 覆盖模块与场景：
  - 归一化/判空：字符串的 null / undefined / 空串 / 纯空白 / 非字符串类型（数字、对象、数组）/ 首尾空白 trim；数字的 0 / 负数 / NaN / 非有限 / 小数 / 数字串 / 含空白数字串；模板的缺 `{host}` / 空串 / 纯空白 / 合法模板；未知键丢弃；整包非对象防御；`reasoningEffort` 永不可配；默认值为空串的字段（端点/密钥/模型）空值仍为空的语义。
  - 读路径 `mergeConfig`：默认全量 + 非空覆盖；任何空/无效值一律回退默认；不存在"空串透传"。
  - 写路径 `pruneConfig`：表单值恒为字符串 → 只保留非空键、数字转 number、字符串 trim、模板缺 `{host}` 被剔除、全空返回空对象、未知键不进入载荷。
  - 配置页 DOM（jsdom）：给定存储对象 → 有值字段 value 为存储值、无值字段 value 为空且 placeholder 为默认值、混合存储下各字段互不影响；「恢复默认」单击后该组输入框为空且 placeholder 出现。
- 先例：既有配置测试与 jsdom 测试装置（`tests/helpers/`），以及内容脚本测试里"给定 DOM/存储 → 断言可见结果"的写法。
- 既有用例的改写：依赖旧双语义的 3 条（空串回退 vs 透传、纯空白透传、`mergeConfigRaw` UI 语义）改为新语义；数字坏值、未知键、`reasoningEffort`、旧键丢弃等用例保持。

## Out of Scope

- 存储读写失败（配额超限、sync 冲突）的错误提示与重试——保持现状（console + 本地日志）。
- 多设备同步冲突合并策略、同步时机。
- 配置文件导入/导出、多套配置、密钥加密存储。
- 并发上限的控件形态改造（下拉/滑杆/范围提示），本次只改判空与回显语义。
- 未配置守卫的触达方式（仍是每宿主的 error 通道 + 配置页指引）与 ADR-0005 的"每宿主一次请求"模型。
- 历史已写入存储的默认模板字面量的自动迁移/清理——用户清空模板并保存即可解冻，本次不做自动迁移。
- 数字字段的"上限"校验（超大值仍被并发池按宿主数收敛，不新增 UI 约束）。

## Further Notes

- 本次把 ADR-0003 两次 "Evolved" 累积出的两条读取语义收敛回一条；「恢复默认」首次成为真正的解冻路径（此前唯一解冻姿势是手动清空 textarea 再保存）。
- 刻意的取舍：判空收紧后，"把纯空白当作有意的值"被禁掉（此前 `targetLang: "   "` 会原样进提示词）。空白的唯一解释是"未设置"。
- 与 html-wrapper-protocol 正交：包装协议管输入/输出格式，本 spec 管配置读写语义。
- 风险面：配置页以前不做存储写入失败处理，本次也不做；`storage.sync` 报错时保存会静默失败（仅 console 有记录），这是已知且被显式排除的内容。
