# 01: 空即未设置——配置核心归一化，读写两条路径收敛

**What to build:** 用户清空任一配置项并保存后，存储里不再有该键（全部为空时 `config` 键本身消失），翻译时该项回退内置默认，重开配置页显示为空。纯空白、类型错误、数值非法这类"伪值"同样算空：端点/密钥/模型填了纯空白后，右键翻译得到的是"未配置 …——左键点击扩展图标打开配置页"的指引，而不是发往扩展自身地址的莫名错误。一条判空规则同时服务写路径（保存）与读路径（翻译时读取与配置页回填），不再存在第二套语义。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 配置模块对外只留四个契约：**归一化入口**（默认值 + 原始值 → 只含有效键、值已归一化的新对象，非对象/数组/字符串原始值一律视为空）、**读路径合并**（默认全量 + 归一化结果）、**写路径剪枝**（表单值 → 存储载荷：数字字段转 number、字符串字段 trim）、**存储读取**（取同步存储里的 `config` 原始对象，缺失返回 null）。
- [x] "空"的定义按默认值类型界定，且**只有一处实现**，读写两条路径都经由它：字符串必须是字符串且 trim 后非空（null / undefined / 数字 / 对象 / 数组 / 纯空白一律为空）；数字必须是有限、大于 0 的**整数**（数字串可接受，0 / 负数 / 小数 / NaN / 非有限 / 非数字串 / 空串为空）；提示词模板在字符串规则之上还必须包含 `{host}`，缺占位符等同留空。
- [x] 表驱动测试用同一批用例同时喂读路径与写路径，断言两者对"空 / 非空"的判断完全一致——这是"判空不漂移"的自动化保障，也是本工单的核心测试形态。
- [x] 配置页保存：空字段不进入载荷；载荷为空对象时**删除** `config` 键（不是写入空对象）；有非空字段时整包写入（旧键、已删除的键随之被清掉，无需迁移逻辑）。
- [x] 配置页回填：输入框显示存储中真实存在的非空值；未设置的字段 value 为空。
- [x] 运行时读取（后台代理与内容脚本共用同一读路径）对存储中的空/非法值一律得到默认值，因此纯空白的端点/密钥/模型会被未配置守卫拦下，不发起任何网络请求。
- [x] 配置页 jsdom 测试夹具建立（注入 jsdom 文档 + `chrome.storage` 替身后动态加载配置页模块），用来断言"清空字段保存 → 存储里没有该键 / 全空 → `config` 键被删除"与"有值字段回填显示值、未设置字段为空"两条端到端行为。
- [x] 旧的双语义读取（UI 回填专用加载器与运行时加载器）及其导出被删除，全仓无引用、无命名残留；`reasoningEffort` 仍永不可配；未知键（如历史 `batchSize`）不进入归一化结果。
- [x] 保存反馈说明本次因空而删除的项数。
- [x] `npm test` 全绿（lint + node:test）：依赖旧双语义的既有用例改写为新语义，数字坏值 / 未知键 / `reasoningEffort` / 旧键丢弃等用例保持。
