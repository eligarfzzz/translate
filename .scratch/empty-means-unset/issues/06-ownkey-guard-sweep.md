# 06: 收掉辅助函数里的原型链假绿——`Object.hasOwn` 扫尾

**What to build:** 工单 05 把两条**守门断言**从 `in` 改成了自有属性判断，但同一文件里还有两处**变量键**的 `in` 判断，属于工单 05 评审发现 (a) 指出的同一类洞：它们查的是配置模块产出的普通对象（`{}` 字面量），而 `in` 会沿原型链查找，于是**键名若恰为 `Object.prototype` 的成员（`toString`、`constructor`…），判断会撒谎**——声称"该键还在"，而该键其实已被归一化丢弃。本票把这两处收掉，并补一条会**先红后绿**的回归数据，让这个洞从此由测试守着而不是由"恰好没有这种数据"守着。

具体三件事：

1. **`normalizationDrops` 辅助函数**（评审 (a) 原文所指）。它现在的写法是 `!(key in sanitizeStored(...))`，键是变量。改成只查自有属性。改成 `Object.hasOwn` 之后，`normalizationDrops("toString", "x")` 才会如实返回"已丢弃"。

2. **"判空不漂移"用例里的同类写法**。同一文件内 `key in out` 形式、键同样来自用例表变量、`out` 同样是 `sanitizeStored` / `pruneConfig` 的产物，所以是同一个洞的第二个实例。一并改为自有属性判断。

3. **补一条回归数据，让洞被测试守住**：在"其余字段"用例表里加入一个**原型成员名的未知键**（`toString` 之类，原始值任意），期望"判定恒假 + 归一化仍然丢弃"。这条数据在旧写法下**必然转红**（旧写法会说"没丢弃"），改成自有属性判断后转绿——它正是本票的存在理由，也是防止将来有人改回去的守门。

**明确不做（连同理由写进代码注释）**：

- **不往"判空不漂移"的用例表里加原型成员名数据**。那个用例的读路径断言是"取值后与默认值比较"，而 `merged["toString"]` 与默认值表的 `["toString"]` 都经原型链解析到同一个函数，比较必然通过、**断言变得空洞**，反而制造"已验证"的假象。该洞由第 3 条那条数据（在"其余字段"表里）负责守。
- **字面量键的 `in` 断言保持原样**：`batchSize` / `maxCharsPerBatch` / `apiKey` / `reasoningEffort` / `model` / `promptTemplate` 这些写法里的键是代码里写死的常量，不可能与原型成员重名；工单 05 已明确此类保持原样，本票不推翻。
