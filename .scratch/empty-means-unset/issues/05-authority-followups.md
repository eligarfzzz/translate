# 05: 工单 04 评审的收口——守卫不重复、最后一处默认值副本、守门断言与用例名

**What to build:** 工单 04 建立了"规则只有一处实现"，评审 PASS 后留下五条非阻断发现。本票把它们收口，每一条都是独立的小改动，合起来的效果是：**规则本体一处、守卫一处、`src/` 里不再有任何"空 → 默认值"的副本、守门断言不再被原型链骗过、用例名与它实际断言的事实一致。**

1. **入参守卫不再写两遍**（评审 S2）。今天公开谓词（判断某字段的原始值是否因缺占位符被判空）内部重做了类型与空白判断，而调用它的归一化实现（已经算好 trim 后的非空字符串）紧接着又调用了同一个谓词，于是同一组守卫在调用方与被调方各有一份，可以独立漂移。改成两层：内核只负责"已保证是非空字符串时是否缺占位符"这一件事，公开谓词负责类型与空白守卫后委托内核，归一化实现直接调用内核。**对外行为完全不变**——空白与非字符串仍判定为 false（配置页的空模板因此继续走通用文案而非专门文案）。

2. **`src/` 里最后一处"空 → 默认值"副本**（评审 S3）。内容脚本从读路径拿到生效配置后，又写了一遍"空就用 20"。读路径已保证该字段是正整数（默认值 20 来自默认值表），所以这个 `|| 20` 是冗余的第三份知识，去掉它。

3. **守门断言改用自有属性判断**（评审 S4）。两条守门用 `in`，会沿原型链查找：若某字段名恰为 `toString` / `constructor`，守门会误判通过，而真正消费默认值表的地方（按自有键遍历）会把它丢弃——正是守门要拦的那种漂移。改用只查自有属性的判断方式。凡断言的是"默认值表确有/没有某个键"这类语义的地方保持原样。

4. **保存反馈里裸数字 1 的语义具名化**（评审 S6）。模板缺占位符的专门文案会额外报"另有 N 项为空"，其中 N 由"被判空项数减一"得来（减掉模板自身，它已由专门文案报过）。今天那个 `1` 是裸字面量，读者要靠上下文才知它是"模板本身"。改成具名表达，语义不变。

5. **用例名收窄到它真正断言的事实**（评审 PARTIAL，本票唯一涉及测试语义的项）。现在的表驱动用例声称"非空字符串域上同真同假"，但该**双向**等价对非占位符字段并不成立：把并发上限填成 `"abc"`、写入不可配置的字段、写入未知键，都是"判定为假、而归一化仍会丢弃"。现有用例表恰好绕开了这类输入，所以今天为绿——但这是**靠数据回避而非靠断言正确**，后人按票面往表里补一条 `["concurrency", "abc"]` 就会误红，而去"修"实现迎合这条过强声明又会破坏配置页文案。改为：**对声明需要占位符的字段断言双向等价，对其余字段断言"判定恒假"（而归一化是否丢弃不作绑定）**，并把此前被回避的那类输入补进用例表，让它们成为受保护的绿。必须成立的那条单向蕴含（判定为真 ⟹ 归一化丢弃）予以保留。
