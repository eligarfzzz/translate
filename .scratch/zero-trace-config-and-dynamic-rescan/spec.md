# Spec: 零痕迹配置 + 动态内容重扫修复

## Problem Statement

两个独立问题：

1. 扩展以代码内默认值的形式内置了真实网关端点（IP）与 API 密钥，任何拿到仓库或安装包的人都能直接提取。虽然配置决策 ADR 记录过"v1 接受、勿用生产凭证"，但 owner 现决定清理仓库（git 历史由 owner 自行压缩），要求工作区的代码、测试、文档不再含任何真实配置值；且今后经配置页写入的配置只存浏览器存储，不产生任何仓库文件痕迹。

2. 翻译会话期内页面动态变化（拖动、展开动态节点）时常常不加载翻译。两个根因：其一，重扫的防抖到期时若上一轮翻译仍在流式进行，本次扫描被静默丢弃且不再重新调度——翻译期间出现的新内容永久漏翻；其二，页面观察器只监听子节点新增，以 display/class/隐藏属性切换实现的展开（无新增节点）根本不触发重扫。

## Solution

1. 端点、密钥、模型三项默认值清空为无凭证占位；未配置任一项时翻译入口给出含配置页指引的明确错误（走既有批次错误通道）；配置页照常经浏览器 sync 存储覆盖默认值——该链路本就零仓库痕迹。代码、测试、文档中不再出现真实端点、密钥、模型名。

2. 重扫调度改为"忙则重试"：防抖到期遇翻译进行中，重新排队直至空闲再扫，页面静止后自然收敛；观察器补充属性变化监听（class/style/hidden/open），展开类属性切换同样触发重扫；扩展自身注入物的变化仍被过滤，防抖保证高频抖动页面不产生请求风暴。

## User Stories

1. 作为扩展 owner，我希望仓库内任何文件都不含真实 API 端点、密钥、模型名，这样压缩 git 历史后仓库可公开而不泄露网关信息。
2. 作为扩展 owner，我希望默认配置是空占位，这样任何克隆仓库的人拿不到可用凭证。
3. 作为扩展用户，我在配置页填入端点/密钥/模型后，希望配置只保存在浏览器 sync 存储中，不产生任何仓库文件改动。
4. 作为扩展用户，我希望未配置端点/密钥/模型任一项时点「翻译页面」，译文位置显示明确的"未配置"错误与打开配置页的指引，而不是模糊的网络错误。
5. 作为扩展用户，我希望配置页「恢复默认」回到空默认值，表单同步显示为空。
6. 作为扩展用户，我希望导出的运行日志不含明文密钥（既有脱敏行为保持不变）。
7. 作为扩展开发者，我希望配置合并逻辑（空默认 + 非空覆盖）继续被既有测试把关，默认值清空不破坏任何既有测试。
8. 作为页面读者，初始翻译仍在流式输出时页面新增了内容（展开动态节点、插入节点），我希望翻译结束后这些内容也被翻译，不永久漏翻。
9. 作为页面读者，翻译完成后我展开一个折叠面板（display/class/hidden 切换、details 的 open 属性），面板内英文被翻译。
10. 作为页面读者，拖动重排导致框架重建节点时，新节点被翻译；已有译文节点随宿主移动不丢失。
11. 作为页面读者，翻译进行中的重试调度不会无限循环：页面静止且翻译全部结束后，调度收敛停止，不产生持续空扫。
12. 作为页面读者，扩展自身注入的译文容器与动画不触发重扫风暴。
13. 作为页面读者，class/style 高频抖动的页面（动画密集站点）不因属性监听产生翻译请求风暴，防抖仍然生效。
14. 作为页面读者，「还原」后监听与调度清理干净，会话外的页面变化绝不触发任何翻译（安全边界不变）。
15. 作为页面读者，重扫触发的翻译仍遵守批次独立原则：某批失败只影响该批宿主，其余照常完成。

## Implementation Decisions

- 默认配置中端点、密钥、模型三项清空为空字符串；目标语言与批次参数等无害默认保留。合并逻辑不变：存储中非空字符串照常覆盖空默认，类型防御规则原样生效。
- 批次代理入口加未配置守卫：三项任一为空时该批直接以错误消息回告（走既有批次错误通道），不发起网络请求；错误文案包含打开配置页的指引。
- 重扫调度拆分：防抖回调独立为扫描执行体；到期时会话仍活跃但翻译进行中时，重新排队同样时长再试而非丢弃；扫描产出空批次时自然结束，页面静止后调度收敛。
- 观察器订阅扩展：子节点新增监听维持；新增属性变化监听，限定 class/style/hidden/open 属性过滤器；属性变化的目标位于本扩展译文容器子树内则忽略；所有触发共用同一防抖入口。
- 宿主去重策略（已翻宿主登记表）不动——"向已翻译宿主内追加内容不重翻"是已知盲区，明确出范围。
- 文档同步：配置决策 ADR 追加演进注记（默认值清空、真实配置仅存浏览器存储、仓库零凭证）；README 配置表改为"默认空、配置页填写"；日志脱敏测试中的真实密钥片段改为虚构样例。
- 零痕迹承诺的边界：代码/测试/文档不含真实值；git 历史清理由 owner 自行压缩提交完成；旧密钥的作废与轮换在网关侧操作。

## Testing Decisions

- 好的测试只断言外部行为：消息与端口输入（翻译/还原/流式增量/完成）到 DOM 输出（译文容器出现与否），不断言内部函数与调度器状态等实现细节。
- 测试接缝：沿用既有最高接缝——jsdom 沙箱按 manifest 顺序加载全部 content script，增强三处测试基建：可编程的消息监听捕获、可控时序的 mock 批次端口（可停在流式中途再放行完成）、元素几何补丁（jsdom 的 getBoundingClientRect 恒为零会使宿主被判不可见）。
- 新增两个回归用例：① 翻译流式进行中注入新宿主节点，断言最终出现译文容器（修复前红）；② 对已存在但隐藏的英文块移除隐藏属性（无节点新增），断言触发翻译（修复前红）。
- 既有全部测试（配置合并、日志脱敏、宿主发现、条目装配等）保持绿色作为回归门槛。
- 未配置守卫不新增自动化测试：入口处三行判定走既有错误通道，人工验证错误呈现；为其引入新接缝的成本高于回归价值。
- Prior art：加载顺序冒烟测试（沙箱加载模式与全局符号契约）、宿主发现测试（jsdom 注入 document 与样式）。

## Out of Scope

- 已翻宿主内追加内容不重翻（需内容指纹与旧译文替换决策）——本轮连工单都不建，留待未来单独发起。
- git 历史压缩与提交清理（owner 自行完成）。
- 旧密钥在网关侧的作废与轮换。
- 配置页 UI 的任何改动（输入框、校验、提示文案）。
- 端点强制 HTTPS、连通性预检等配置校验增强。
- 思考开关可配置化（既定永不可配）。

## Further Notes

- 零痕迹是"工作区清理 + owner 压缩历史"的组合结果：仓库文件清理完成后，历史中的旧值依赖 owner 的 squash 才彻底消失。
- A/B 修复后仍存在的已知盲区（已翻宿主内追加内容）应在文档中可见，避免未来误报为回归。
- 观察器属性过滤器未来若发现更多展开型属性，扩充过滤器即可，无需改调度逻辑。
