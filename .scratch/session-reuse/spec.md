# Spec: 会话重用（session-reuse）——可选的每槽会话链与失败重试

## Problem Statement

- 现状（ADR-0005）：每个宿主是**一次完全独立的无状态请求**——`messages` 只有一条 user（完整渲染的模板+单段），并发池 N 个 worker 互不相干。模型每段从零开始，没有页面上下文，术语与风格前后不一。
- 用户要「重用会话」：**同一并发槽位内**先后处理的段串成一条对话——前段的原文+译文作为历史，模型只翻最新文本。默认关；关时行为与今天**逐字节一致**。
- 长链有两个已知失败模式，共用同一个兜底：**上下文超限**（请求体随链长线性增长，终有触顶的一刻）与**模式漂移**（模型不再继续"翻译"模式，回显不带 `<html>` 包装）。两者都"弃掉历史、新开会话重试"。
- 即便不开会话重用，"回显不带包装"目前是被宽容渲染的（把废话连同译文一起写进页面）——用户要求改成**重试一次、再败报错**。

## Solution

### 1. 会话与并发：每槽一条链

- 并发池（`runPool`）的 N 个 worker 各自持有一条链；worker 内串行：上一段落定后才取下一个任务，新段带着**本槽**的历史。
- 6 段 abcdef、并发 3：槽 1 链 a→d→g，槽 2 链 b→e→…，槽 3 链 c→f→…——即 `[ad][be][cf]`。槽间互不相干。
- "上一次翻译的上下文" = **本槽位上一个成功段**，不是文档序上一个，也不是全局上一个。无竞态。

### 2. 消息形态：链首与链中

链首（每槽第一段、或重试开启的新会话）——与今天一字不差：

```
messages = [{ role: "user", content: renderPrompt(模板, 段html, { target, extra }) }]
```

链中——纯对话形态，最新一轮**不带模板**：

```
messages = [
  ...历史对（按链序，最老在前）:
    { role: "user",      content: "<html>段html₁</html>" },   // 与 {host} 注入同形
    { role: "assistant", content: 原始回显₁ },                 // 含包装、未剥壳、未净化
  { role: "user", content: "<html>段htmlₖ</html>" }            // 最新文本：模型只翻它
]
```

- 历史对 = `(段html, 原始回显)`：user 只放原文（不带模板说明文字），assistant 放模型原始输出。模型从对话模式知道该做什么。
- **html wrapper 保持**：每轮 user 文本都是恰一层 `<html>…</html>`（容忍属性/大小写/空白，与 `{host}` 注入同一包装）；回显剥壳（`stripHostWrapper`）、净化、流式预览全部照旧。
- 包装形式的唯一来源是 `prompt.js`：content 侧历史只存**纯数据对** `(段html, 原始回显)`，不包装；background 组装消息时经同一 helper 包装——禁止第二套包装写法。
- 风险记录：个别模型长链后可能不继续翻译模式。Fallback（暂不实装）：每轮补 `system` 消息重复模板；若实测出现模式漂移，重试机制本身已是最常见恢复手段。

### 3. 失败与重试（background 内部，content 不感知）

background 在流式过程中累积全文 `full`（它本来就能看到全部 delta）。收尾时按序判定：

```
HTTP 错误且文案命中"上下文超限"模式
   → 仅会话模式：弃历史、链首形态重试一次；再败 → 既有错误通道
   → 非会话模式：不重试（内容没变长，重试无意义），直接既有错误通道
200 但 full 非空、且 trim 后整体不是恰一层 <html>…</html>（与 stripHostWrapper 同一判定）
   → 两种模式都重试一次：会话模式 = 弃历史（= 新会话）；非会话模式 = 同请求重发
   → 再败 → 既有错误通道
200 且形态合规 → 正常 done
```

- 每种触发器**各重试一次**；重试在 background 内部完成，content 只看到一次 `done` 或一次 `error`。
- **落定收口不变**：每宿主恰好一次 settle，重试不占额外计数；失败段（含重试失败）**不进链**。
- 重试成功后，该段成为**新链首**：它之后的段以它为链首继续累积。
- 空回显（`""` 或 `<html></html>`）**不重试**：维持既有「未返回译文」专属口径。
- 行为变化（明说）：现在"包装外带废话"的回显会被宽容渲染成译文；新逻辑下 = 重试一次，再败报错。content 侧宽容渲染路径保留为纵深防御（正常不再命中）。
- 超限文案匹配保守列举（`context length` / `maximum context` / `token limit` / `too many tokens` / `context window` 等，大小写不敏感），随网关演进可增补；测试以固定样例守门。

### 4. 链的生命周期与归属

- 链是 **content 侧**每个 worker 的内存状态（数组），随 start 消息把纯数据历史发给 background。**不让 background 存链**：它是跨标签页共享的，存链要按 (tab, generation, 槽位) 建键并保证释放，等于自造串台与泄漏隐患。
- 链随一轮翻译：点「翻译」开新一轮（generation 已天然区分），还原/页面刷新即弃。配置改动不影响进行中的链（下一轮生效）。
- 失败段不进链，所以链 = 该槽位**成功段**的有序序列。

### 5. 配置：`reuseSession`

- 键 `reuseSession`，默认 `false`（关）；配置页 **API** TAB（紧邻并发——它改的是请求形态），控件 checkbox，标签「重用会话」。
- 「空即未设置」扩展出**布尔规则**：`normalizeValue` 新增分支——只认 `true`/`false`；字符串（含 `"true"`）、数字、null 等一律视为未设置。保存时未勾选 = 删键 = 回退默认 false；勾选 = 写 `true`。未勾选且存储原本为 `true` 时，照旧计入保存反馈的「已删除 N 项设置」。
- 不新增可配置项：重试次数、窗口、超限文案都不可配（写死一次/无限/保守清单）。

## User Stories

- 作为用户，我希望同一区域的段落由同一条"会话"连续翻译，前后术语与风格一致，而不是每段都从零开始。
- 作为用户，我希望正文翻完就能读到正文（见 badge-timer）；会话重用是译文**质量**选项，不影响进度口径。
- 作为用户，页面很长、链很长时，如果上下文超限或模型跑偏，它能自己弃历史重开一局，而不是把废话写进我的页面。
- 作为用户，不开这个选项时，一切与今天完全一致。

## Implementation Decisions

- **D1 配置形状**：`reuseSession` / 默认 `false` / API TAB / checkbox「重用会话」；`GROUPS.api.fields` 末尾追加。
- **D2 布尔判空**：`normalizeValue` 布尔分支只认 boolean；读路径缺键 → `false`；写路径 `false` → 删键。`EMPTY_DEFAULT_PLACEHOLDERS` 守门不破：布尔默认非空串，不进示例清单（清单只约束其中的键）。
- **D3 链 = 并发槽位**：worker 持链；链序 = 该 worker 取任务的先后；`translateEntries(entries, limit, reuse)` 透传开关（content.js 从 cfg 读取）。
- **D4 消息形态**：链首同今日；链中 = 历史对 + 裸新文本（无模板）；历史对 user = 包装原文、assistant = 原始回显；包装 helper 唯一来源 `prompt.js`。
- **D5 分工**：content 发 `{ type:"start", text, history:[{html, echo}] }`（`history` 仅会话模式且非空时携带）；background 渲染链首 / 组装链中 / 判定与重试。**端口协议增两处**（实施中修订）：start 的一个可选字段 `history`，以及 background → content 的控制消息 `{type:"restart"}`（"本轮尝试作废、本槽会话重开"）。后者是必需的：delta 是增量追加、`done` 时才剥壳，失败尝试已流式送出的预览撤不回；`restart` 双重职责——① 清空本段累积回显与预览；② 作废本槽已累积的链（`chain.length = 0`）。没有 ② 则"重试成功段成为新链首"不成立：形态触发器会让后续段继续带着漂移掉的历史，超限触发器会让每段必然再触顶一次。其余协议与行为不变。
- **D6 重试**：两触发器（超限仅会话模式；形态两种模式）、各一次、链首形态、background 内部、content 不感知、落定一次、失败不进链、成功段成新链首。实施中两条精确化：① 超限重试的实际门是"本请求**携带了历史**"（`history.length > 0`）——链首无历史可弃，重试内容与首次逐字相同，故不重试；② 形态重试两种模式都适用，因此"关 = 与现状逐字节一致"只对**请求形态**成立（关着时形态不符也会产生第二次请求）。重试前统一发一次 `restart`（两个触发器共用同一条恢复路径，超限路径下它同时承担清链职责）。
- **D7 不重试的空回显**：`""`/`<html></html>` 维持「未返回译文」，无重试；形态判定与 `stripHostWrapper` 同源（导出共用谓词），禁止第二套"什么是包装"。
- **D8 生命周期**：链随 generation；还原/刷新丢弃；配置改动不影响在途链。实施中精确化：`reuseSession` 与 `concurrency` 在**轮次开始时**读取，而请求时配置（端点/密钥/模型/模板/目标语言等）仍逐请求读取——沿用 ADR-0003 的既有口径。
- **D9 新 ADR-0007**：记录动机（术语一致性/质量）、纯客户端 messages 累积（**不用服务端 session id**）、每槽一链、失败不进链、重试语义，以及与 ADR-0005 的关系——ADR-0005 的"一宿主一次端点请求"是**成功路径**的计数口径（落定/进度收口），失败恢复的重试是额外地请求，两者不冲突。
- **D10 Fallback 记录**：模式漂移的 system 消息方案只记录在案，不实装；重试已是第一线恢复手段。
- **D11 零痕迹**：文档/测试不得出现真实端点、密钥、厂商模型名。

## Testing Decisions

- 配置（新布尔分支）：`[reuseSession, true, true]`、`[false, undefined]`（删键）、`["true", undefined]`、`[1, undefined]`、`[null, undefined]`；`mergeConfig` 缺键 → `false`；`pruneConfig` 往返；守门测试（示例清单的键默认必须为空串）保持绿。
- 配置页：checkbox 回填（stored true → checked）、保存往返（勾选 → 存 true；取消勾选 → 删键）、恢复默认（清空组 → unchecked）、保存反馈计数（原本 true 被取消 → 计入已删除）。
- 消息组装（mock fetch，断言请求体）：链首 = 单条 user（与今日相同）；链中 = 历史对 + 裸文本；历史对顺序 = 链序；包装与 `{host}` 注入同形。
- 链行为（驱动 translator，stub 端口/background）：abcdef 并发 3 → 槽 1 第二段带 `[{a}]`；失败段不进链（b 失败后 e 的历史无 b）；重试成功段成新链首。
- 重试：形态不符 → 恰两次上游请求（会话模式第二次无历史；非会话模式第二次同请求）；再败 → error；空回显 → 一次请求、未返回译文；超限（mock 400+文案）→ 会话模式两次请求、第二次无历史；非会话模式一次请求直接报错；重试不占 settle 计数（落定收口每宿主恰好一次）。
- **关 = 不变**：`reuseSession` 缺省/ false 时，既有全部测试逐字绿、上游请求数不变（一宿主一次）。
- 先红后绿：新断言在旧实现下必须红（旧实现没有 history 字段/重试）。
- 断言落在可见结果与请求体上，不断言内部实现。

## Out of Scope

- 服务端 session id / Assistants API / 任何网关私有的会话机制。
- 重试次数可配、历史窗口（无限累积是已定决策）、超限文案可配。
- 空回显重试；非会话模式的超限重试。
- `system` 消息 Fallback（D10 只记录）。
- 跨标签页/跨会话共享链；链的持久化落盘；按档位分链。
- 进度徽标、翻译优先级、包装协议、净化、落定收口的任何改动。

## Further Notes

- 性能：链中请求体随链长线性增长，全页总输入 O(n²)——用户已确认接受（术语一致性的代价）；默认并发 20 = 最多 20 条独立链。
- 与 badge-timer 无交互：落定口径（每宿主恰好一次）不变，重试不产生新的 settle。
- 调试：重试经 debug 通道留痕（触发器、第几次尝试），便于真机排查。
- 还原/刷新时 background 无残留状态（链在 content 侧随页面死亡自然消失；background 只持 in-flight 请求的 AbortController，照旧）。
