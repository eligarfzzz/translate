# Spec: 短文本缓存（short-text-cache）——background IndexedDB 短原文缓存

## Problem Statement

- 现状（ADR-0005）：每个宿主是一次完全独立的流式请求，每次都携带完整模板头。导航项、按钮、页脚链接这类**短原文**在同一页面反复出现、跨页面逐字重复——一句 30 字节的 "Sign in" 与一整段文字支付同样的模板与往返开销。
- 同一原文在相同配置下的译文是确定的，但现状没有任何缓存：刷新页面、重访站点、打开另一篇文章，所有短文本全部重新请求。
- 用户要一个本地缓存：短原文命中即回，未命中才走端点，并自动过期、自动限容——不需要用户做任何维护。

## Solution

在 background service worker 里建一个跨页面的 IndexedDB 缓存：**骨架原文 ≤ 阈值的宿主**先查缓存，命中则把缓存回显当作一次「极快的翻译」回放给 content（一条 delta + done），未命中照常走上游、成功后写入。每个条目带一个命中即刷新的时间戳，连续一个月没人用才过期；总量超上限时按最久未用淘汰。每个会话首轮翻译全部落定后自动清理一次。开关默认开，可在配置页关闭；阈值/上限/过期天数均可配置。决策已记入 ADR-0008。

## User Stories

1. 作为用户，我希望跨页面反复出现的短文本（导航、按钮等）直接命中本地缓存，这样重访网站时不再为它们付出 API 请求。
2. 作为用户，我希望缓存默认开启，不做任何配置就能受益。
3. 作为用户，我希望配置页有一个开关能彻底关闭缓存（不查、不写、不清）。
4. 作为用户，我希望条数上限（默认 10000）、过期天数（默认 30）、字节阈值（默认 30）都能在配置页调整。
5. 作为用户，我希望换了模型 / 目标语言 / 提示词后不再吃到旧译文，这样永远不会看到错语言的缓存结果。
6. 作为用户，我希望一直命中的热条目一直活着，没人用的条目一个月后被清掉。
7. 作为用户，我希望缓存总量有上限，磁盘占用不无限增长。
8. 作为开了「重用会话」的用户，我希望缓存命中的段落不被当作对话历史回发给模型。
9. 作为用户，我希望缓存命中与普通翻译看起来毫无区别：译文节点照常渲染、进度徽标照常计数。
10. 作为用户，我希望数据库出故障时翻译照常进行，缓存静默降级而不是报错。
11. 作为用户，我希望失败或空回显的翻译永远不进缓存，错误不会被冻结下来反复回放。
12. 作为用户，我希望清理由扩展在每页翻译结束后自动做一次，而不是我要手动维护的功能。

## Implementation Decisions

- **D1 存储选址**：background worker 的 IndexedDB（扩展源，跨页面共享）。否决 content 侧 IndexedDB（属页面源：每站一份、该站脚本可读可写，且无跨页共享）与 `chrome.storage.local`（无索引，过期/淘汰需自维护元数据记录）。库内单个 object store：键 = `指纹 + 分隔符 + 骨架原文`，值 = `{ echo, lastUsedAt }`，`lastUsedAt` 建索引供清理扫描。指纹 = apiBase / model / targetLang / promptTemplate / extra 五项拼接的不可逆散列（apiKey 不进指纹——密钥不塑造译文）；零痕迹姿势不受影响。
- **D2 查询门槛**：`cacheEnabled`（默认 `true`）开启，且骨架原文（`entry.html`，含标签、无 `<html>` 包装，background 侧 trim 后）UTF-8 字节数 ≤ `cacheMaxBytes`（默认 30）才查、才写；更长的宿主永远直走上游。
- **D3 查询位置**：background 的 `start` 处理器内——未配置守卫之后（指纹需要已加载的配置；未配置时即使库里有也走既有错误通道）、fetch 之前。命中：刷新 `lastUsedAt`，回发一条 delta（缓存原始回显全文）+ `done{cached:true}`。content 的预览 / 定稿 / 落定收口 / 进度徽标零改动。
- **D4 写入条件**：仅 `requestWithRetry` 成功收尾（回显非空、恰一层 `<html>` 包装，含重试后的获胜尝试）才写；错误 / 空回显 / 中止不写。存的是含包装的原始回显（与入链回显同形），命中路径因此复用 `stripHostWrapper` 与净化，不存在第二套剥壳。为此 `requestWithRetry` 改为返回获胜尝试的累积全文（纯内部重构，端口协议不变）。
- **D5 协议扩展**：`done` 增加可选标志 `cached: true`（无新消息类型）。content 在定稿渲染照旧，但 `cached` 为真时跳过 `chain.push`——缓存命中段**永不进入会话重用的链**（reuse 开启时缓存照常查写，这是 Q4=B 的决策；命中段不回发给模型，这是 Q12 的决策）。槽位前几段全命中时，链从第一个未命中段开始累积。
- **D6 过期与淘汰（LRU）**：每条目单时间戳 `lastUsedAt`——写入时记下、每次命中刷新。过期 = 距今超过 `cacheTtlDays`（默认 30 天，命中续期）；超出 `cacheMaxEntries`（默认 10000）时按 `lastUsedAt` 从最旧淘汰到上限。上限仅在清理 pass 执行，一轮内可短时超限（最多一轮的短文本写入量），接受。
- **D7 清理触发**：每会话首轮 `runRound`（该轮全部宿主落定）后，content 向 background 发一条 `cleanup-cache` 消息；background 收到且缓存开启时执行一次（删过期 + 淘超限）。重扫不再触发；开关关闭时不发、不清。
- **D8 配置面**：四个新键全部落在配置页「通用」TAB——`cacheEnabled` 复选框（短文本缓存，默认开）+ `cacheMaxEntries` / `cacheTtlDays` / `cacheMaxBytes` 三个正整数输入。「空即未设置」照章适用：清空 + 保存 = 删键 = 回退版本默认。改动不追溯存量：缩小上限 / 缩短过期等下次清理生效；改阈值只影响之后的查询与写入（已存条目查不到、自然过期）。
- **D9 布尔归一化镜像推广**：`normalizeValue` 布尔分支推广为「仅存非默认面」——默认 `false` 的字段（reuseSession）只有 `true` 落盘（行为逐字节不变）；默认 `true` 的字段（cacheEnabled）只有显式 `false` 落盘，勾选回默认态 + 保存 = 删键。CONTEXT.md「空即未设置」词条与 ADR-0003 追加段已同步此修订。
- **D10 降级**：IndexedDB 打开 / 读写的任何失败 → 记日志并按「无缓存」继续翻译；缓存故障永远不得在页面上表现为错误，也不得阻断请求。
- **D11 不做在途合并**：同一轮里 N 个相同短原文仍各发一次请求（首个成功写入后，后续轮次才命中），v1 接受。
- **D12 零痕迹**：代码 / 测试 / 文档不出现真实端点、密钥、厂商模型名；指纹散列不可逆，缓存键不泄露可读配置。

## Testing Decisions

- 好测试的标准沿用仓库口径：只断言外部可观察行为（端口消息次序与载荷、DOM、存储载荷、配置归一化结果），不断言内部状态。
- **配置归一化**：既有 `tests/config.test.js` 纯函数接缝——镜像布尔（默认 `true` 字段存 `false` 落盘 / `true` 删键；默认 `false` 字段行为不变）与三个数值键（正整数规则、非法回退）的新用例。
- **配置页**：既有 `tests/options.test.js` 接缝（jsdom），含反向守门「默认值表的键必须有同名表单字段」——四个新控件与回填/保存/恢复默认行为。
- **缓存存储模块**：新模块以工厂注入 IndexedDB 句柄（与 debug.js 注入 storage 同构——node 无 IndexedDB），测试用内存假实现驱动：写入 / 命中刷新 `lastUsedAt` / 过期删除 / LRU 淘汰到上限 / 指纹隔离。
- **background 集成**：既有 `tests/helpers/background-sandbox.js`（chrome / fetch / 端口替身）——命中回放的消息次序（delta 全文 + done.cached）、未命中成功后写入、失败与空回显不写、改配置后旧键不命中、IndexedDB 抛错时照常翻译。
- **content 集成**：既有 `tests/helpers/content-sandbox.js`（jsdom + 端口替身 + 手动时钟）——`done.cached` 段跳过入链（下一请求不带该段历史）、首轮落定后 cleanup 消息恰好一次、重扫不再发、开关关闭时不发。
- 先红后绿；`npm test` 全绿后由 docs 票按**实测**用例数更新 AGENTS.md。

## Out of Scope

- 在途合并（同轮相同短原文的去重）——D11 明确接受重复请求。
- 手动清空缓存的 UI 按钮（DevTools 可清；等真实需求再加）。——**已搬进范围**：由 cache-manual-clear 落地（见 `.scratch/cache-manual-clear/spec.md`），配置页「通用」TAB 已有「清空缓存」按钮（整库清空、与开关无关、回应条数；契约见 `docs/adr/0008-short-text-cache.md` 的 Evolved 段）。
- 长文本（超阈值）缓存、整页快照缓存。
- 跨设备同步（缓存只存本地 IndexedDB，不进 `chrome.storage.sync`）。
- 命中率等统计面板。——**部分搬进范围**：每条缓存的累计命中次数及其在分页缓存表格中的展示由 cache-inspection 落地；全局命中率、未命中次数和独立统计面板仍在范围外（见 `.scratch/cache-inspection/spec.md`）。
- 缓存条目的导入导出。

## Further Notes

- 决策来源：grilling 两轮共十二问（Q1–Q12），要点已记入 `docs/adr/0008-short-text-cache.md`；领域词条「短文本缓存」已进 CONTEXT.md。
- 与会话重用叠加的语义取舍：reuse 开 + 缓存开时，模型读到的链**不含**缓存命中段（Q12）——链的上下文可能因此比「全量真实翻译」短，这是明确的取舍，不是缺陷。
- 指纹未覆盖的请求参数：`temperature` 固定 0.3、`reasoningEffort` 恒 `none` 不可配——两者不影响指纹正确性，故不进指纹。
- 风险记录：同轮大量相同短原文首次出现时仍会各发一次请求（D11），极端页面（数百个互不相同的短宿主）一轮可写入数百条——由上限与清理兜住，不另设速率限制。
