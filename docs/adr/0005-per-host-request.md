# One host, one request — per-host streaming, batch merging removed

Each host is translated by its own streaming request. The prompt is the translation instruction plus that host's skeleton HTML (tag names and text only — attributes stripped per the skeleton serialization); the entire reply is that host's translation: streamed through as a tag-stripped plain-text preview, finalized on `done` with the sanitized HTML written into the host's translation node. There are no `[N]` entry markers and no entry assembly — nothing to misalign. `batching.js`, the entry assembler, and the `batchSize`/`maxCharsPerBatch` config keys are deleted from the whole chain (config, options page, prompt template clause 5 rewritten as a single-segment echo instruction, tests). Failure granularity shrinks to a single host: a failed request marks only that host's node with an italic error. A `runPool` concurrency pool bounds requests in flight (`concurrency`, default 20, configurable in the options page); Revert and the out-of-session safety boundary are unchanged.

This supersedes the batching part of [ADR-0001](./0001-streaming-batched-translation.md) (hosts are no longer merged into multi-entry batches) while continuing its streaming decision (each request still streams, rendering incrementally as tokens arrive). The cost is accepted explicitly: one request per host — a page with N hosts issues N requests — and each request carries the full instruction header; gateway pressure is bounded only by the concurrency pool.
