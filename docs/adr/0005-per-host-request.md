# One host, one request — per-host streaming, batch merging removed

Each host is translated by its own streaming request. The prompt is the translation instruction plus that host's skeleton HTML (tag names and text only — attributes stripped per the skeleton serialization); the entire reply is that host's translation: streamed through as a tag-stripped plain-text preview, finalized on `done` with the sanitized HTML written into the host's translation node. There are no `[N]` entry markers and no entry assembly — nothing to misalign. `batching.js`, the entry assembler, and the `batchSize`/`maxCharsPerBatch` config keys are deleted from the whole chain (config, options page, prompt template clause 5 rewritten as a single-segment echo instruction, tests). Failure granularity shrinks to a single host: a failed request marks only that host's node with an italic error. A `runPool` concurrency pool bounds requests in flight (`concurrency`, default 20, configurable in the options page); Revert and the out-of-session safety boundary are unchanged.

This supersedes the batching part of [ADR-0001](./0001-streaming-batched-translation.md) (hosts are no longer merged into multi-entry batches) while continuing its streaming decision (each request still streams, rendering incrementally as tokens arrive). The cost is accepted explicitly: one request per host — a page with N hosts issues N requests — and each request carries the full instruction header; gateway pressure is bounded only by the concurrency pool.

**Evolved: the request carries only rendered content, and a host with nothing left to translate issues no request at all.** "Tag names and text" above was not the whole truth: the strip list covered only the extension's own inserted nodes, the media tags and the form controls, so a host's descendant `script` / `style` / `noscript` / `iframe` — and anything inside a `<template>`, whose content lives on the `content` document fragment that element traversal and the text-collecting TreeWalker never reach while `innerHTML` serialization does emit it — travelled into the request verbatim. The output-side sanitizer had banned these tags all along, so the same bytes were stripped on the way back but paid for on the way in. Snapshotting now deletes a single fixed list of 非渲染标签 (`script`, `style`, `iframe`, `template`, `noscript`, `link`, `meta`, `base`) with their whole subtrees, plus HTML comments, and that one list is also the exclusion range of the qualification text collection — so text inside those tags no longer counts as host content and a long Chinese script can no longer skew the Chinese-ratio test into skipping an English paragraph. Second narrowing: after the strip, a candidate whose text content is nothing but whitespace (NBSP and zero-width characters included, the same whitespace definition the output-side sanitizer uses, shared as a pure function in `text-utils`) yields no entry — no translation node, no concurrency slot, no share of the progress badge denominator, and no "already processed" registration, so the block is re-evaluated if the page later fills it in. Host qualification and emptiness are deliberately two different ranges: qualification asks what natural-language text the host has apart from pre/code and the strip list, the gate asks what the request would actually contain — the gate therefore also catches the blocks the media step empties. Only the content fed to the model changes; the page's own DOM is never touched, and the output-side sanitizer is unchanged by this.
